<h1 align="center">Babel Content Clipper</h1>

<p align="center"><strong>웹 페이지에서 필요한 부분을 선택해 내 Agent에게 전달하세요.</strong></p>

<p align="center">브라우저 사이드 패널 수집 · 로컬 영구 저장 · MCP 전달</p>

Babel Content Clipper는 Chrome 확장 프로그램과 로컬 MCP 구성 요소를 결합한 도구입니다. 웹을 탐색하면서 선택한 텍스트, 이미지, 페이지 영역, 오디오 및 비디오 시간 범위를 명시적으로 저장할 수 있습니다. 그런 다음 사용자의 Agent가 Job을 가져와 파일을 만들고 처리 결과를 다시 기록합니다.

현재 버전은 `0.1.0-alpha.1`이며 버전이 지정된 GitHub Release 첨부 파일과 소스 빌드 및 로컬 로드 방식을 함께 제공합니다. DSH 연계 솔루션의 일부이지만 독립적으로도 사용할 수 있습니다.

저장소: [GitHub](https://github.com/gjw199513/babel-content-clipper) · 다운로드: [GitHub Releases](https://github.com/gjw199513/babel-content-clipper/releases)

> 현재 예정된 사용 범위는 개인의 비상업적 사용입니다. 상업적 사용에는 저자의 별도 허가가 필요합니다. 정식 라이선스 조건은 아직 확정되지 않았으며, 프로젝트는 현재 `private: true` 및 `UNLICENSED`로 표시되어 있습니다. 사용하거나 배포하기 전에 [라이선스 방향](../../../LICENSE-POLICY.md)(중국어 간체)을 읽어 주세요.

## 인터페이스 미리 보기

사이드 패널에서 빠르게 수집하고 라이브러리를 열어 자세히 관리할 수 있습니다. 아래 이미지는 중국어 로컬 예제 데이터를 사용한 공용 스크린샷이며, 각 언어용으로 새로 촬영한 화면이 아닙니다. 이번 인터페이스는 중국어 간체, English, 繁體中文, 日本語, 한국어를 지원합니다. [중국어 사이드 패널 공용 예제](../../assets/sidepanel-preview.png)도 볼 수 있습니다.

![중국어 예제 데이터를 표시하는 Babel 라이브러리: 소스 그룹, 필터, 레코드 상세 정보](../../assets/library-preview.png)

## 해결하는 문제

북마크만 저장하면 당시 실제로 필요했던 문단을 잃기 쉽고, 스크린샷은 후속 처리가 어렵습니다. Babel Content Clipper는 ‘수집’과 ‘처리’를 분리합니다.

```text
웹 페이지에서 사용자가 명시적으로 선택
    → Chrome 확장 프로그램이 수집해 로컬 IndexedDB에 저장
    → Native Messaging 로컬 브리지
    → MCP 클라이언트의 Agent
    → 각 레코드별로 파일을 출력하고 결과를 다시 기록
```

확장 프로그램은 소스, 원문 또는 미디어 위치를 저장하고 대기 작업과 기록을 관리합니다. Agent는 소스 가져오기, 자르기, OCR, ASR, 요약 또는 기타 후속 작업을 담당합니다. 목록을 조회하거나 알림을 받는 것만으로는 다운로드나 처리가 자동으로 시작되지 않습니다.

## 기능과 경계

| 수집 방식 | 실제로 저장되는 내용 | 알아야 할 경계 |
|---|---|---|
| 선택한 텍스트 | 선택한 전체 텍스트, 제목, 소스 URL, 필요한 페이지 문맥 | 특수 리더에서 선택 영역을 직접 읽을 수 없으면 명시적으로 붙여넣어 가져올 수 있습니다. 알 수 없는 소스는 그대로 표시됩니다 |
| 이미지 및 영역 스크린샷 | 이미지 참조, 설정된 예산 안에서 가져올 수 있는 이미지 바이트 또는 선택 영역의 픽셀 스크린샷 | 이미지는 권한, 교차 출처 제한, 용량 예산의 영향을 받습니다. 스크린샷을 저장했다고 해서 원문을 가져온 것은 아닙니다 |
| 오디오/비디오 구간 | 소스 미디어 식별 정보, 실제 시작·종료 지점, 탐색으로 생긴 구간, 매개변수 스냅샷 | 일반 구간 레코드는 원본 비디오나 오디오를 다운로드했다는 뜻이 아닙니다 |
| 실시간 오디오 및 비디오 | 사용자가 이번 클립에 대해 명시적으로 활성화한 뒤 브라우저가 실제로 캡처한 화면과 소리 | 활성화 전 내용을 되돌려 가져오는 버퍼는 없습니다. 권한 실패나 불완전한 범위는 명확히 기록되며 완전한 소스 파일처럼 표시되지 않습니다 |

핵심 동작:

- 하나의 Capture 안에서 되감기로 겹친 구간은 한 번만 유지됩니다. 다시 수집하거나 명시적으로 ‘재처리’를 선택하면 새 레코드와 결과를 만들 수 있습니다.
- 앞뒤 여유 시간은 설정에서 변경할 수 있습니다. 실제 미디어 범위, 가져오기 계획 범위, 최종 출력 범위는 각각 따로 보존됩니다.
- 사이드 패널에는 빠른 수집과 최근 레코드만 표시합니다. 연결 및 설정은 전용 전체 페이지에서 열리고, 백업 및 유지 관리는 기본적으로 접혀 있습니다. 라이브러리에서 전체 관리를 제공하며 탭을 전환해도 별도의 데이터 사본이 만들어지지 않습니다.
- 레코드를 ‘보관만’으로 설정하면 대기 목록 조회와 알림에서 제외됩니다. 받은 편지함으로 다시 옮겨도 실행은 자동으로 시작되지 않습니다.
- 화면의 처리 상태는 ‘처리 대기, 처리 중, 처리됨, 처리 실패’이며 Job 값 `pending`, `processing`, `completed`, `failed`에 각각 대응합니다. 가져오기는 원자적으로 수행되어 여러 Agent가 같은 작업 항목을 동시에 처리하지 않습니다.
- 각 수집 레코드는 독립적으로 가져오고, 출력하고, 다시 기록합니다. 배치의 한 레코드가 실패해도 다른 레코드의 결과는 취소되지 않습니다.
- 출력 디렉터리는 ‘이번 작업에서 지정 → MCP 연결 기본값 → 확장 프로그램 전역 기본값’ 순서로 결정됩니다. 일회성 재정의는 저장된 기본값을 바꾸지 않습니다.
- 기존 결과와 실패 기록은 나중 처리로 덮어쓰지 않습니다. 성공 후에도 원래 레코드는 자동으로 삭제되지 않습니다.

이 프로젝트에는 ASR, OCR, 요약 서비스, 미디어 다운로더 또는 FFmpeg가 내장되어 있지 않습니다. 사용자가 명시적으로 처리를 요청한 뒤 Agent는 자신의 환경에 이미 있는 도구를 사용할 수 있습니다. 일반 수집에는 FFmpeg가 필요하지 않습니다. 전체 실행 규칙은 [Agent 실행 계약](agent-workflow.md)을 참조하세요.

## 빠른 시작

### 1. 릴리스 패키지 다운로드

- Chrome / Chromium `116` 이상. 이는 최소 Manifest API 버전이며 모든 Chromium 기반 브라우저에서 검증되었다는 뜻은 아닙니다.

일반 사용자는 해당 버전의 [GitHub Releases](https://github.com/gjw199513/babel-content-clipper/releases)에서 `babel-content-clipper-extension-<version>.zip`을 다운로드해 계속 유지할 디렉터리에 압축 해제합니다. 브라우저 수집만 사용할 때는 소스 코드, Node.js, 로컬 빌드가 필요하지 않습니다.

로컬 MCP도 연결하려면 같은 Release에서 `babel-content-clipper-<version>.tgz`도 다운로드하세요. 로컬 구성 요소에는 Node.js `22` 이상이 필요합니다. 개발자는 저장소 루트에서 직접 빌드할 수도 있습니다.

```sh
npm ci
npm run build
```

소스 빌드 결과는 `dist/extension` 및 `dist/node`에 생성됩니다.

### 2. 브라우저 확장 프로그램 로드

1. `chrome://extensions`를 엽니다.
2. ‘개발자 모드’를 켭니다.
3. ‘압축해제된 확장 프로그램을 로드합니다’를 선택합니다. Release 사용자는 ZIP을 푼 뒤 `manifest.json`이 있는 디렉터리를, 소스 사용자는 `dist/extension`을 지정합니다.
4. 도구 모음의 Babel 아이콘을 클릭해 사이드 패널을 엽니다.

MCP를 연결하기 전에도 일반 웹 페이지에서 텍스트를 선택하고, 컨텍스트 메뉴 또는 `Alt+Shift+S`로 저장한 뒤 사이드 패널에서 레코드를 볼 수 있습니다.

압축 해제한 Release를 교체하거나 다시 빌드한 뒤에는 확장 프로그램 관리 페이지에서 ‘새로고침’을 클릭하고 사이드 패널을 다시 여세요. 확장 프로그램을 삭제하는 방식으로 업데이트하면 로컬 데이터도 함께 삭제될 수 있습니다. Chrome은 일반 ZIP을 직접 로드할 수 없습니다. 진정한 원클릭 설치에는 브라우저 스토어나 브라우저가 신뢰하는 기업 배포 채널이 필요합니다.

### 3. 로컬 MCP 연결

사이드 패널에서 ‘라이브러리 열기’를 선택하고 라이브러리의 ‘연결 및 설정’을 연 다음, 현재 브라우저의 `profileId`를 복사합니다. 이 값은 이 컴퓨터의 브라우저 데이터를 구분하기 위한 것이며 웹사이트 계정이 아닙니다.

다음은 macOS + Google Chrome 설치 예시입니다. `YOUR_PROFILE_ID`와 출력 디렉터리를 자신의 값으로 바꾸세요.

```sh
node dist/node/cli.js --mode=install \
  --extension-id lpmplddblefacpachnchfgcdebjebdbh \
  --profile-id YOUR_PROFILE_ID \
  --output-root /absolute/path/to/output \
  --manifest-dir "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts" \
  --mcp-config-out ./babel-clipper-mcp.json
```

확장 프로그램에서 ‘전역 기본 결과물 디렉터리(선택 사항)’를 이미 설정했다면 `--output-root`를 생략할 수 있습니다. 설치 프로그램은 Native Messaging 등록 파일, 시작 스크립트 및 MCP 클라이언트에 바로 병합할 수 있는 설정을 생성합니다.

생성되는 최소 설정 구조는 다음과 같습니다. 실제 파일에는 로컬 Node, CLI, 비공개 설정 디렉터리의 절대 경로와 현재 `profileId`가 기록됩니다. 아래 자리 표시자 경로를 복사하지 말고 생성된 결과를 사용하세요.

```json
{
  "mcpServers": {
    "babel-content-clipper": {
      "command": "/absolute/path/to/node",
      "args": [
        "/absolute/path/to/babel-content-clipper/dist/node/cli.js",
        "--mode=mcp",
        "--config-dir",
        "/absolute/path/to/private-config",
        "--profile-id",
        "YOUR_PROFILE_ID"
      ]
    }
  }
}
```

`babel-clipper-mcp.json`의 `mcpServers` 아래 항목을 사용하는 MCP 클라이언트 설정에 병합하세요. 그런 다음 라이브러리에서 ‘로컬 서비스 다시 연결’을 선택하고 클라이언트 연결을 시작하거나 새로 고칩니다. 다음 명령으로 전체 연결 경로를 진단할 수 있습니다.

```sh
node dist/node/cli.js --mode=doctor --profile-id YOUR_PROFILE_ID
```

진단 결과가 `ready: true`이고 확장 프로그램도 연결 성공을 표시해야 해당 `profileId`의 연결 경로가 준비된 것입니다. 다른 브라우저와 운영체제의 Native Messaging 경로, Windows 레지스트리 단계, 문제 해결 방법은 [설치 및 첫 연결](install.md)을 참조하세요.

### 4. 첫 전달 완료

1. 웹 페이지에서 텍스트를 선택하고 `Alt+Shift+S`를 눌러 저장합니다.
2. Agent에게 “Babel Clipper의 미처리 레코드를 조회해 줘”라고 요청합니다. 조회만으로는 Job을 가져오지 않습니다.
3. 대상 레코드를 확인한 뒤 “이 선택 텍스트를 텍스트 파일로 저장하고 결과를 다시 기록해 줘”처럼 처리를 명시적으로 요청합니다.
4. 라이브러리로 돌아와 ‘처리됨’ 상태와 이번 실행의 결과물 기록을 확인합니다.

## 자주 쓰는 작업

| 작업 | 기본 진입점 |
|---|---|
| 선택한 텍스트 저장 | `Alt+Shift+S` 또는 웹 페이지 컨텍스트 메뉴 |
| 미디어 구간 기록 시작 / 종료 | `Alt+Shift+V`; 첫 번째는 시작, 두 번째는 종료 |
| 페이지 영역 선택 | `Alt+Shift+X` |
| 사이드 패널 열기 | 브라우저 도구 모음의 Babel 아이콘 클릭 |
| 라이브러리 열기 | 사이드 패널 오른쪽 위의 ‘라이브러리 열기’ |
| 여유 시간, 알림, 예산 및 출력 디렉터리 설정 | 라이브러리의 ‘연결 및 설정’ |

macOS 키보드에서는 Option이 여기서 말하는 Alt에 해당합니다. 바로 가기가 운영체제나 다른 확장 프로그램에 할당되어 있을 수 있으므로 브라우저의 확장 프로그램 단축키 설정 페이지를 기준으로 확인하세요. 실시간 오디오 및 비디오를 저장하려면 먼저 ‘이번에 라이브 오디오와 비디오도 저장’을 활성화하고 대상 웹 페이지에서 현재 탭 권한을 부여해야 합니다. 라이브러리 페이지에서 부여한 권한은 대상 페이지 권한을 대신하지 않습니다.

## 인터페이스 언어

Babel Content Clipper 인터페이스는 중국어 간체(`zh-CN`), English(`en`), 繁體中文(`zh-TW`), 日本語(`ja`), 한국어(`ko`) 사이에서 전환할 수 있습니다.

- 처음 사용할 때는 ‘브라우저 설정 따르기’(`auto`) 모드가 기본으로 선택되며 브라우저의 기본 로케일을 따릅니다. 지원하지 않는 로케일은 English로 대체됩니다.
- 수동으로 선택한 언어는 현재 브라우저 profile에 영구 저장되고 사이드 패널, 라이브러리, ‘소개 및 도움말’에 함께 적용됩니다.
- ‘브라우저 설정 따르기’를 다시 선택하면 브라우저 언어를 자동으로 따르는 상태로 돌아갑니다. `auto` 모드의 대체 언어는 계속 English입니다.
- 언어 선택은 인터페이스와 도움말 텍스트만 바꿉니다. 수집한 웹 콘텐츠, 파일명, 기술 매개변수 또는 MCP 키는 번역하지 않습니다.
- 브라우저의 확장 프로그램 관리 페이지에 표시되는 설명과 단축키는 브라우저 자체의 인터페이스 언어를 따릅니다. 확장 프로그램 안에서 언어를 선택해도 브라우저 언어는 바뀌지 않습니다.
- 라이브러리의 ‘소개 및 도움말’에서 선택한 언어의 내장 안내를 열고 해당 언어의 `install.md`를 오프라인용으로 다운로드할 수 있습니다.

## 호환 범위

현재 빌드의 최소 Chromium 버전은 `116`입니다. 전체 로컬 연결 경로는 macOS, Node.js 22 및 Chrome for Testing 153 환경에서 검증되었습니다. 이 결과가 다른 시스템, 브라우저 버전 또는 Chromium 기반 브라우저의 지원을 자동으로 의미하지는 않습니다.

공개 웹 페이지 샘플에서는 다음 항목을 각각 검증했습니다.

- Bilibili, YouTube: 텍스트 수집 및 미디어 시간 범위 기록. 해당 샘플에서는 어느 사이트에서도 원본 비디오를 다운로드하지 않았습니다.
- Zhihu, 중국 대학 MOOC, Coursera: 공개 페이지의 텍스트와 설정된 예산 안의 이미지 수집. 해당 강의 페이지 샘플은 로그인 후 콘텐츠나 강의 비디오의 호환성을 입증하지 않습니다.

Windows, Linux, Firefox, Safari, 원격 Agent 및 모바일 브라우저는 아직 검증된 조합에 포함되지 않습니다. 사이트별 로그인 상태, 교차 출처 iframe, Canvas, 제한된 미디어, 사용자 지정 리더도 각각 확인해야 합니다. 계속 갱신되는 [호환성 매트릭스](../../compatibility.md)와 [인수 검증 범위](../../acceptance.md)(중국어 간체)를 참조하세요.

## 데이터 흐름 및 개인정보 보호

- Capture, Job, Result, 설정 및 확장 프로그램 첨부 파일은 현재 브라우저 profile의 IndexedDB에 저장됩니다.
- 확장 프로그램은 로컬 Native Messaging을 통해 로컬 MCP 프로세스와 통신합니다. 로컬 브리지 설정에는 비공개 연결 정보가 들어 있으므로 저장소에 커밋하거나 다른 사람과 공유하면 안 됩니다.
- 일반적인 웹 페이지 수집을 지원하기 위해 확장 프로그램은 HTTP/HTTPS 페이지 접근 권한을 선언합니다. 수집은 사용자의 명시적 동작으로 시작됩니다. 이미지 바이트는 브라우저 자격 증명 없이 원래 웹 주소에서 가져올 수 있습니다.
- 이 프로젝트에는 클라우드 동기화나 원격 측정 서비스가 내장되어 있지 않습니다. 콘텐츠를 외부 Agent, 모델 또는 도구에 전달한 뒤의 데이터 처리는 해당 구성 요소와 사용자 설정에 따라 달라집니다.
- 웹 페이지 텍스트, HTML 및 첨부 파일은 항상 신뢰할 수 없는 데이터로 전달됩니다. 페이지 내용에 포함된 지시는 사용자 승인이 아닙니다.
- 확장 프로그램을 제거하거나 브라우저 데이터를 지우면 로컬 레코드가 삭제될 수 있습니다. 백업을 내보낼 때 내부 첨부 데이터를 포함할지 선택할 수 있습니다. 외부 Agent가 생성한 파일은 확장 프로그램 백업에 포함되지 않습니다.

## 프로젝트 구조

| 경로 | 역할 |
|---|---|
| `apps/extension` | Chrome MV3 확장 프로그램, 사이드 패널, 라이브러리, 수집, 실시간 녹화 |
| `packages/core` | 데이터 계약, IndexedDB, 상태 머신, 시간 범위, 트랜잭션 규칙 |
| `packages/mcp` | MCP stdio 서비스, Native Messaging, 로컬 broker, 설치, 진단 |
| `docs` | 설치, 아키텍처, 호환성, Agent 계약, 인수 검증, 제품 사양 |
| `scripts` | 빌드, 정적 검사, 테스트 픽스처 서비스, 로컬 패키징 |
| `tests` | Core, MCP, 통합, 브라우저 검증 |
| `config/extension-identity.json` | 개발 빌드의 안정적인 확장 프로그램 공개 키 및 ID |

## 개발, 검증 및 패키징

```sh
# 타입 검사, Core/통합 테스트, LSP 검증 및 빌드
npm run check

# 브라우저 테스트를 처음 실행하기 전에 테스트 브라우저 설치
npx playwright install chromium
npm run test:browser

# 선택 사항: 지정된 공개 웹 페이지 샘플 온라인 확인
npm run test:platform

# 로컬 소비자 설치 검증
npm run verify:install

# Release에 올릴 버전이 포함된 확장 프로그램 ZIP, MCP tgz, 5개 언어 안내문, 메타데이터, 소스 매니페스트, 체크섬을 생성하고 검증
npm run package:release
```

`npm run package:release`는 로컬 파일만 생성합니다. 코드를 업로드하거나 npm 패키지를 게시하거나 원격 Release를 만들지 않습니다. 브라우저 자동화 결과도 대상 사이트, 대상 브라우저 및 실제 로그인 환경의 인수 검증을 대신할 수 없습니다.
