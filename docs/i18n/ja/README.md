<h1 align="center">Babel Content Clipper</h1>

<p align="center"><strong>Web ページの必要な部分を、あなたの Agent へ。</strong></p>

<p align="center">ブラウザーのサイドパネルで収集 · ローカルに永続保存 · MCP で引き渡し</p>

Babel Content Clipper は、Chrome 拡張機能とローカル MCP コンポーネントを組み合わせたツールです。Web の閲覧中に、選択したテキスト、画像、ページ領域、音声・動画の時間範囲を明示的に保存できます。その後、自分の Agent が Job を取得し、ファイルを生成して処理結果を書き戻します。

現在のバージョンは `0.1.1` で、バージョン付きリリース添付ファイルに加え、ソースからのビルドとローカル読み込みも利用できます。DSH 連携ソリューションの一部ですが、単独でも利用できます。

リポジトリ：[GitHub](https://github.com/gjw199513/babel-content-clipper) · ダウンロード：[GitHub Releases](https://github.com/gjw199513/babel-content-clipper/releases)

> 現在想定している利用範囲は、個人による非商用利用です。商用利用には作者から個別に許諾を得る必要があります。正式なライセンス条項は未確定で、プロジェクトには現在 `private: true` と `UNLICENSED` が設定されています。利用または配布の前に[ライセンス方針](../../../LICENSE-POLICY.md)（簡体字中国語）を確認してください。

## 画面プレビュー

サイドパネルですぐに収集し、ライブラリを開いて詳しく管理できます。以下は中国語のローカルサンプルデータを使った共通画像で、各言語向けに新たに撮影したスクリーンショットではありません。今回のインターフェースは、簡体字中国語、English、繁體中文、日本語、한국어に対応しています。[中国語のサイドパネル共通サンプル](../../assets/sidepanel-preview.png)も表示できます。

## 解決する問題

ブックマークでは、その時に本当に必要だった段落が失われがちです。一方、スクリーンショットは後から加工しにくい形式です。Babel Content Clipper は「収集」と「処理」を分離します。

```text
Web ページで明示的に選択
    → Chrome 拡張機能が収集してローカル IndexedDB に保存
    → Native Messaging のローカルブリッジ
    → MCP クライアント内の Agent
    → レコードごとに個別ファイルを出力し、結果を書き戻す
```

拡張機能はソース、原文またはメディア位置を保存し、保留中の作業と履歴を管理します。メディアが必要な場合、Agent は MCP 経由で接続中の Babel 拡張機能に取得を依頼し、書き出した後に自分のツールで切り出し、OCR、ASR、要約などの後処理を行います。リストを照会したり通知を受け取ったりするだけでは、取得や処理は自動的に始まりません。

## 機能と境界

| 収集方法 | 実際に保存される内容 | 理解しておくべき境界 |
|---|---|---|
| 選択テキスト | 選択した全文、タイトル、ソース URL、必要なページコンテキスト | 特殊なリーダーで選択範囲を直接取得できない場合は、明示的に貼り付けてインポートできます。不明なソースは不明のまま表示されます |
| 画像と領域スクリーンショット | 画像参照、設定された上限内で取得できた画像バイト、または選択領域のピクセル画像 | 画像は権限、オリジン間制限、容量上限の影響を受けます。スクリーンショットを取得しても原文を取得したことにはなりません |
| 音声・動画の範囲 | ソースメディアの識別情報、実際の開始・終了位置、シークで生じた区間、パラメーターのスナップショット | 通常の範囲記録は、元の動画や音声をダウンロードしたことを意味しません |
| ライブ映像・音声 | ユーザーが今回のクリップ用に明示的に有効にした後、ブラウザーが実際にキャプチャした映像と音声 | 有効化前の内容を遡るバッファーはありません。権限エラーや不完全な範囲は明示的に記録され、完全なソースファイルとして扱われることはありません |

主な動作：

- 1 回の Capture 内では、見直しによる重複範囲は 1 回だけ保持されます。再度収集するか、明示的に「再処理」を選ぶと、新しいレコードと結果を作成できます。
- 前後の余白時間は設定で変更できます。実際のメディア範囲、取得予定範囲、最終出力範囲は個別に保持されます。
- サイドパネルにはクイック収集と最近のレコードだけを表示します。接続と設定は専用の全画面ページで開き、バックアップとメンテナンスは初期状態で折りたたまれます。ライブラリで一括管理でき、タブを切り替えても別のデータは作られません。
- レコードを「保存のみ」にすると、保留中の照会と通知から除外されます。受信トレイに戻しても、処理は自動的に始まりません。
- 画面上の処理状態は「未処理、処理中、処理済み、処理失敗」で、Job 値 `pending`、`processing`、`completed`、`failed` に対応します。取得はアトミックに行われるため、複数の Agent が同じ作業項目を同時に処理しません。
- 各収集レコードは個別に取得、出力、書き戻しされます。バッチ内の 1 件が失敗しても、ほかのレコードの結果は取り消されません。
- 出力ディレクトリは「今回のタスクで指定 → MCP 接続の既定値 → 拡張機能のグローバル既定値」の順に解決されます。今回だけの上書きで、保存済みの既定値は変更されません。
- 既存の結果や失敗履歴は後続の処理で上書きされません。成功後も元のレコードは自動的には削除されません。

このプロジェクトにクラウド ASR、OCR、要約サービスは組み込まれていません。MCP は収集内容のエクスポート、構造化された処理ガイド、claim 検証、接続中の Babel 拡張機能への取得依頼を提供します。Agent は `babel_clipper_acquire_source_media` の後に `babel_clipper_export_capture` を呼び、拡張機能の添付ファイルをローカルへ書き出してから FFmpeg、sherpa-onnx、LLM などの後処理を行います。Agent 自身のダウンローダー、CUA、Playwright、Puppeteer、ブラウザーのクリック操作で元メディアを取得してはいけません。完全な規則は [Agent 実行契約](agent-workflow.md)と[拡張機能取源 Spec](../../specs/Babel_Content_Clipper_Browser_Extension_Acquisition_Spec_2026-09-21.md)を参照してください。

## クイックスタート

### 1. リリースパッケージをダウンロードする

- Chrome / Chromium `116` 以降。これは Manifest API の最低バージョンであり、すべての Chromium 派生ブラウザーで検証済みという意味ではありません。

一般ユーザーは該当バージョンの [GitHub Releases](https://github.com/gjw199513/babel-content-clipper/releases) から `babel-content-clipper-extension-<version>.zip` をダウンロードし、保持するディレクトリに展開します。ブラウザーでの収集だけなら、ソースコード、Node.js、ローカルビルドは不要です。

ローカル MCP にも接続する場合は、同じ Release から `babel-content-clipper-<version>.tgz` もダウンロードします。ローカルコンポーネントには Node.js `22` 以降が必要です。開発者はリポジトリのルートからビルドすることもできます。

```sh
npm ci
npm run build
```

ソースからのビルド結果は `dist/extension` と `dist/node` に出力されます。

### 2. ブラウザー拡張機能を読み込む

1. `chrome://extensions` を開きます。
2. 「デベロッパー モード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を選択します。Release の場合は ZIP 展開後の `manifest.json` を含むディレクトリ、ソースの場合は `dist/extension` を指定します。
4. ツールバーの Babel アイコンをクリックしてサイドパネルを開きます。

MCP に接続する前でも、通常の Web ページでテキストを選択し、コンテキストメニューまたは `Alt+Shift+S` で保存して、サイドパネルでレコードを確認できます。

展開した Release を置き換えた場合や再ビルドした後は、拡張機能管理ページで「再読み込み」をクリックし、サイドパネルを開き直してください。拡張機能を削除して更新すると、ローカルデータも削除される可能性があります。Chrome は通常の ZIP を直接読み込めません。真のワンクリックインストールには、ブラウザーストアまたはブラウザーが信頼する企業配布経路が必要です。

### 3. ローカル MCP に接続する

サイドパネルで「ライブラリを開く」を選び、ライブラリの「接続と設定」を開いて、現在のブラウザーの `profileId` をコピーします。これはこのコンピューター上のブラウザーデータを区別する ID であり、Web サイトのアカウントではありません。

以下は macOS + Google Chrome 用のインストール例です。`YOUR_PROFILE_ID` と出力ディレクトリを自分の値に置き換えてください。

```sh
node dist/node/cli.js --mode=install \
  --extension-id lpmplddblefacpachnchfgcdebjebdbh \
  --profile-id YOUR_PROFILE_ID \
  --output-root /absolute/path/to/output \
  --manifest-dir "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts" \
  --mcp-config-out ./babel-clipper-mcp.json
```

拡張機能で「グローバル既定の出力ディレクトリ（任意）」を設定済みであれば、`--output-root` は省略できます。インストーラーは Native Messaging の登録ファイル、起動スクリプト、MCP クライアントにそのまま統合できる設定を生成します。

生成される最小設定の構造は次のとおりです。実際のファイルには、ローカルの Node、CLI、プライベート設定ディレクトリへの絶対パスと現在の `profileId` が書き込まれます。以下のプレースホルダーパスをコピーせず、生成結果を使用してください。

```json
{
  "mcpServers": {
    "babel-content-clipper": {
      "command": "/absolute/path/to/node",
      "args": [
        "/absolute/path/to/babel-content-clipper/dist/node/cli.js",
        "--mode=mcp",
        "--config-dir",
        "/absolute/path/to/private-config",
        "--profile-id",
        "YOUR_PROFILE_ID"
      ]
    }
  }
}
```

`babel-clipper-mcp.json` の `mcpServers` 配下の項目を、自分の MCP クライアント設定に統合します。その後、ライブラリで「ローカルサービスに再接続」を選択し、クライアント接続を開始または更新します。次のコマンドで接続経路全体を診断できます。

```sh
node dist/node/cli.js --mode=doctor --profile-id YOUR_PROFILE_ID
```

診断で `ready: true` が返り、拡張機能側も接続成功を示した場合に限り、その `profileId` の接続経路が準備完了です。ほかのブラウザーや OS の Native Messaging パス、Windows のレジストリ手順、トラブルシューティングは、[インストールと初回接続](install.md)を参照してください。

### 4. 最初の引き渡しを完了する

1. Web ページでテキストを選択し、`Alt+Shift+S` を押して保存します。
2. Agent に「Babel Clipper の未処理レコードを照会」するよう依頼します。照会だけでは Job は取得されません。
3. 対象レコードを確認してから、「この選択テキストをテキストファイルとして保存し、結果を書き戻す」のように、処理を明示的に依頼します。
4. ライブラリに戻り、「処理済み」の状態と今回の成果物履歴を確認します。

## よく使う操作

| 操作 | 既定の入口 |
|---|---|
| 選択テキストを保存 | `Alt+Shift+S` または Web ページのコンテキストメニュー |
| メディア範囲の記録を開始 / 終了 | `Alt+Shift+V`。1 回目で開始、2 回目で終了 |
| ページ領域を選択 | `Alt+Shift+X` |
| サイドパネルを開く | ブラウザーのツールバーにある Babel アイコンをクリック |
| ライブラリを開く | サイドパネル右上の「ライブラリを開く」 |
| 余白、通知、上限、出力ディレクトリを設定 | ライブラリの「接続と設定」 |

macOS キーボードでは、Option がここでいう Alt に相当します。ショートカットが OS や別の拡張機能で使用されている場合があるため、ブラウザーの拡張機能ショートカット設定を正としてください。ライブ映像・音声を保存するには、先に「今回のみライブ音声・映像も保存」を有効にし、対象の Web ページで現在のタブへの権限を付与します。ライブラリページでの許可は、対象ページへの許可にはなりません。

## 表示言語

Babel Content Clipper のインターフェースは、簡体字中国語（`zh-CN`）、English（`en`）、繁體中文（`zh-TW`）、日本語（`ja`）、한국어（`ko`）を切り替えられます。

- 初回は「ブラウザーに合わせる」（`auto`）モードが選ばれ、ブラウザーの優先ロケールに従います。対応していないロケールでは English にフォールバックします。
- 手動で選択した言語は現在のブラウザー profile に保存され、サイドパネル、ライブラリ、「このアプリと使い方」に共通して反映されます。
- もう一度「ブラウザーに合わせる」を選ぶと、ブラウザーの言語に自動追従する状態へ戻ります。`auto` モードのフォールバックは引き続き English です。
- 言語設定で変わるのは画面とヘルプのテキストだけです。収集済みの Web コンテンツ、ファイル名、技術パラメーター、MCP キーは翻訳されません。
- ブラウザーの拡張機能管理画面にある説明とショートカットの表示は、ブラウザー自体の表示言語に従います。拡張機能内の言語設定でブラウザーの言語は変わりません。
- ライブラリの「このアプリと使い方」から、選択中の言語による内蔵ガイドを開き、その言語の `install.md` をオフライン閲覧用にダウンロードできます。

## 互換性の範囲

現在のビルドが必要とする Chromium の最低バージョンは `116` です。ローカル接続経路全体は、macOS、Node.js 22、Chrome for Testing 153 で検証済みです。この結果から、ほかの OS、ブラウザーバージョン、Chromium 派生ブラウザーの対応を自動的に判断することはできません。

公開 Web ページのサンプルでは、次の項目を個別に検証しています。

- Bilibili、YouTube：テキスト収集とメディア時間範囲の記録。元メディアの取得は接続中の Babel 拡張機能の経路を使用し、過去の Agent 直接ダウンロード検証は現在の本番経路の証拠とはしません。
- Zhihu、中国大学 MOOC、Coursera：公開ページのテキストと、設定した上限内の画像収集。これらのコースページのサンプルは、ログイン後のコンテンツやコース動画への対応を証明するものではありません。

Windows、Linux、Firefox、Safari、リモート Agent、モバイルブラウザーは、まだ検証済みの組み合わせに含まれていません。各サイトのログイン状態、クロスオリジン iframe、Canvas、制限付きメディア、独自リーダーも個別に確認する必要があります。随時更新される[互換性マトリクス](../../compatibility.md)と[受け入れ検証範囲](../../acceptance.md)（簡体字中国語）を参照してください。

## データフローとプライバシー

- Capture、Job、Result、設定、拡張機能の添付ファイルは、現在のブラウザー profile の IndexedDB に保存されます。
- 拡張機能は Native Messaging を介してローカル MCP プロセスと通信します。ローカルブリッジ設定には非公開の接続情報が含まれるため、リポジトリにコミットしたり他人と共有したりしないでください。
- 一般的な Web ページを収集できるよう、拡張機能は HTTP/HTTPS ページへのアクセス権限を宣言しています。収集にはユーザーの明示的な操作が必要です。画像バイトは、ブラウザー資格情報を付けずに元の URL から取得される場合があります。
- このプロジェクトには、クラウド同期やテレメトリーサービスは組み込まれていません。コンテンツを外部の Agent、モデル、ツールに渡した後のデータ処理は、それらのコンポーネントとユーザー自身の設定に依存します。
- Web ページのテキスト、HTML、添付ファイルは、常に信頼できないデータとして引き渡されます。ページ内の指示はユーザーによる承認ではありません。
- 拡張機能の削除やブラウザーデータの消去により、ローカルレコードが削除される可能性があります。バックアップのエクスポート時に内部添付データを含めるか選択できます。外部 Agent が生成したファイルは拡張機能のバックアップ対象ではありません。

## プロジェクト構成

| パス | 役割 |
|---|---|
| `apps/extension` | Chrome MV3 拡張機能、サイドパネル、ライブラリ、収集、ライブ録画 |
| `packages/core` | データ契約、IndexedDB、ステートマシン、時間範囲、トランザクション規則 |
| `packages/mcp` | MCP stdio、Native Messaging、ローカル broker、インストール／診断、Capture 書き出し、ソース引き渡し、Agent ガイド |
| `docs` | インストール、アーキテクチャ、互換性、Agent 契約、受け入れ検証、製品仕様 |
| `scripts` | ビルド、静的チェック、テスト素材サービス、ローカルパッケージ作成 |
| `tests` | Core、MCP、統合、ブラウザー検証 |
| `config/extension-identity.json` | 開発ビルドの安定した拡張機能 ID と公開鍵 |

## 開発、検証、パッケージ作成

```sh
# 型チェック、Core/統合テスト、LSP 検証、ビルド
npm run check

# ブラウザーテストの初回実行前にテスト用ブラウザーをインストール
npx playwright install chromium
npm run test:browser

# 任意：指定した公開 Web ページのサンプルをオンラインで確認
npm run test:platform

# ローカルの利用側インストールを検証
npm run verify:install

# Release にアップロードできるバージョン付き拡張機能 ZIP、MCP tgz、5 言語の説明、メタデータ、ソースマニフェスト、チェックサムを生成して検証
npm run package:release
```

`npm run package:release` が生成するのはローカルファイルだけです。コードのアップロード、npm パッケージの公開、リモート Release の作成は行いません。ブラウザー自動化の結果も、対象サイト、対象ブラウザー、実際のログイン環境での受け入れ確認に代わるものではありません。
