# インストールと初回接続

[简体中文](../../install.md) · [English](../en/install.md) · [繁體中文](../zh-TW/install.md) · [日本語](install.md) · [한국어](../ko/install.md)

このガイドでは `0.1.0-alpha.1` のコマンドラインインターフェースを使用します。実際に検証した OS、ブラウザー、クライアントは[互換性マトリクス](../../compatibility.md)（簡体字中国語）を参照してください。現在は開発候補版であり、npm には公開されていません。

## 1. リリースパッケージをダウンロードする、またはソースを準備する

一般ユーザーは該当バージョンの [GitHub Releases](https://github.com/gjw199513/babel-content-clipper/releases) から `babel-content-clipper-extension-0.1.0-alpha.1.zip` をダウンロードし、保持するディレクトリに展開してください。ブラウザーでの収集だけなら、ソースコード、Node.js、ローカルビルドは不要です。

ローカル MCP に接続する場合は、同じ Release から `babel-content-clipper-0.1.0-alpha.1.tgz` もダウンロードします。ローカルコンポーネントには Node.js 22 以降が必要です。`node --version` が正常に実行できることを確認してください。ブラウザーでの収集自体は FFmpeg に依存しません。Agent が音声や動画を切り出す場合は、その実行環境にすでにあるメディアツールを使用します。

ソースディレクトリからビルドします。

```sh
npm ci
npm run build
```

Release の MCP パッケージをインストールする場合は、自分のインストールディレクトリで次のコマンドを実行します。ファイル名は実際に取得したパッケージのパスに置き換えてください。

```sh
npm install /absolute/path/babel-content-clipper-0.1.0-alpha.1.tgz
```

ソース方式のローカルコンポーネントは `dist/node/cli.js`、パッケージ方式では `node_modules/babel-content-clipper/dist/node/cli.js` にあります。以下ではソース方式の相対パスを使用するため、コマンドはソースのルートで実行してください。

## 2. 拡張機能を読み込み、接続 ID を取得する

ブラウザーの拡張機能管理ページで「デベロッパー モード」を有効にし、「パッケージ化されていない拡張機能を読み込む」を選びます。ソース方式では `dist/extension`、Release 方式では `manifest.json` を含む ZIP 展開済みディレクトリを指定します。Chrome は通常の ZIP を直接読み込めません。ソースは不要ですが、先に展開する必要があります。真のワンクリックインストールには、ブラウザーストアまたはブラウザーが信頼する企業配布経路が必要です。

Babel のサイドパネルを開き、「ライブラリを開く」を選択してから「接続と設定」を開きます。表示されているブラウザー接続 ID `profileId` をコピーします。これはブラウザーごとのデータを区別するためのもので、Web サイトのアカウントではありません。

このビルドの拡張機能 ID は `lpmplddblefacpachnchfgcdebjebdbh` です。ただし、拡張機能管理ページに実際に表示される ID と照合してください。ビルドの key を変更した場合は、自分の ID を使用する必要があります。

この時点で、通常の Web ページ上のテキストを選択し、コンテキストメニューまたは `Alt+Shift+S` で保存できます。MCP に未接続でも、拡張機能はレコードを保存して表示できるはずです。

ソースを更新したり拡張機能ビルドを入れ替えたりした後は、拡張機能管理ページで対象拡張機能の「再読み込み」をクリックし、サイドパネルを開き直してください。ブラウザーウィンドウを開き直すだけでは、新しいコードが読み込まれたことの確認になりません。更新のために拡張機能データを削除しないでください。

## 3. ローカルブリッジをインストールし、クライアント設定を生成する

以下の `YOUR_PROFILE_ID` を前の手順で取得した接続 ID に置き換えます。インストーラーは Native Messaging の登録ファイル、起動スクリプト、MCP 設定例を生成します。既存ファイルは既定で保護されます。`INSTALL_TARGET_EXISTS` が返された場合は、既存ファイルが今回のインストールに属するものか先に確認し、自分の以前のインストールを更新するときだけ `--overwrite` を使用してください。

macOS / Google Chrome：

```sh
node dist/node/cli.js --mode=install \
  --extension-id lpmplddblefacpachnchfgcdebjebdbh \
  --profile-id YOUR_PROFILE_ID \
  --manifest-dir "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts" \
  --mcp-config-out ./babel-clipper-mcp.json
```

Chromium を使う場合は `--manifest-dir` を `$HOME/Library/Application Support/Chromium/NativeMessagingHosts` に変更します。Edge では `$HOME/Library/Application Support/Microsoft Edge/NativeMessagingHosts` を使います。各ブラウザーは固有の登録ディレクトリを読み取ります。

Linux で一般的な場所は、`$HOME/.config/google-chrome/NativeMessagingHosts`、`$HOME/.config/chromium/NativeMessagingHosts`、`$HOME/.config/microsoft-edge/NativeMessagingHosts` です。配布経路によって別のディレクトリが使われることがあります。Linux は、互換性マトリクスに従った実機検証がまだ必要です。

Windows では同じ CLI でファイルを生成し、該当ブラウザーの Native Messaging ホスト用ユーザー別レジストリキーの既定値を、生成した JSON ファイルの絶対パスに設定します。CLI 出力の `manualBrowserLocations` に、対応するレジストリキーが示されます。Windows でのホスト起動と登録は、このプロジェクトではまだ実機検証されていません。ファイルを生成しただけでは対応済みとはみなしません。

インストールに成功すると、`nativeHost.manifestPath`、`nativeHost.launcherPath`、`mcpConfig.path` を含む JSON がターミナルに返されます。コンポーネントのインストールディレクトリを移動または削除しないでください。生成された設定は絶対パスを使用します。

`babel-clipper-mcp.json` の `mcpServers` 配下の項目を、クライアント自身の MCP 設定に統合します。設定ファイルの場所と外側の形式はクライアントごとに異なるため、そのクライアントが提供する MCP 設定画面を使用してください。生成される `command` はローカル Node の絶対パスです。引数にはコンポーネント、設定ディレクトリ、`profileId` が含まれます。作者のコンピューター上のパスを入力する必要はありません。

出力ディレクトリは次のいずれか 1 つの方法で指定します。

- ライブラリの「接続と設定」で「グローバル既定の出力ディレクトリ（任意）」を設定する。
- インストール時に `--output-root /absolute/path/to/output` を追加して MCP の既定ディレクトリを保存する。または、特定クライアントの MCP 起動引数に `--output-root` を追加し、その接続だけの既定値を上書きする。
- 1 回の処理タスクについて、ユーザーまたは Agent が絶対ディレクトリを明示する。

解決順序は、タスク指定、MCP 既定値、拡張機能のグローバル既定値です。今回だけの上書きで既定値は変わりません。明示したディレクトリが利用できない場合は、別の場所に暗黙に保存せず、エラーを返します。

たとえば、あるクライアントだけに別の接続既定値を設定できます。

```sh
node dist/node/cli.js --mode=mcp --profile-id YOUR_PROFILE_ID --output-root /absolute/path/to/client-output
```

これは stdio サービスの起動コマンドで、通常は MCP クライアントが実行します。拡張機能のグローバル設定や、ほかのクライアントの設定は変更されません。

## 4. 接続経路全体を確認する

インストール後、ライブラリの「接続と設定」で「ローカルサービスに再接続」を選び、クライアントの MCP 接続を開始または更新します。続けて次を実行します。

```sh
node dist/node/cli.js --mode=doctor --profile-id YOUR_PROFILE_ID
```

インストールで `--config-dir` を使用した場合は、診断でも同じ引数を指定します。結果に `ready: true` が含まれ、拡張機能の診断も成功した場合に限り、選択した profile の接続経路全体が準備完了です。ブラウザー未接続、設定エラー、ホスト未起動は、それぞれ別の状態として返されます。

Agent に「Babel Clipper の未処理レコードを照会」するよう依頼します。照会だけでは Job の取得や処理は行われません。先ほど保存した選択テキストを Agent が読めることを確認した後、「この選択テキストをテキストファイルとして保存し、処理結果を書き戻す」と明示的に依頼します。Agent は[実行契約](agent-workflow.md)に従って Job を取得し、成果物を保存し、結果をコミットします。ライブラリに処理済み状態と今回の履歴が表示されることを確認してください。

## トラブルシューティング

| 症状 | 確認項目 |
|---|---|
| `PROFILE_REQUIRED` または profile の不一致 | 現在のブラウザーのライブラリから `profileId` をコピーし、クライアント引数を確認します。別のテスト profile は使用できません。 |
| Native Host が見つからない | 登録ディレクトリが現在のブラウザー用か、JSON 内の拡張機能 ID、起動スクリプトのパスと実行権限を確認し、再接続します。 |
| `BROKER_UNAVAILABLE` | 拡張機能のローカル接続または MCP クライアントを起動します。doctor は状態を確認するだけで、バックグラウンド起動は行いません。 |
| `BROWSER_UNAVAILABLE` | 対応するブラウザーと拡張機能を実行したままにし、ライブラリでローカルサービスの接続状態を確認します。このエラーは未処理項目が空であることを意味しません。 |
| `WRITEBACK_UNACKNOWLEDGED` または書き戻し中の切断 | 元の `requestId` と完全に同じ結果内容を保持し、再接続後に冪等に再送します。永続化 ACK を受け取るまで完了と報告しないでください。 |
| 処理中のまま Agent が切断された | 元の実行がまだ動作しているかを先に確認します。タイムアウトだけで、システムが自動的に解放または重複実行することはありません。 |
| Web ページを収集できない | ブラウザー内部ページ、権限制限ページ、特殊なリーダーにはアクセスできない場合があります。明示的に表示される代替手段を使ってください。スクリーンショットが原文になることはありません。 |
| `TAB_CAPTURE_PERMISSION_REQUIRED` | 録画する Web ページに戻り、ブラウザーのツールバーにある Babel 拡張機能アイコンをクリックして、今回のクリップのライブ保存を有効にします。そのページでテキストを選択し、実際のショートカットで先に収集してから、サイドパネルで録画を開始することもできます。この経路は現在の受け入れ検証を通過しています。権限要求は対象の Web ページで行う必要があります。ライブラリページで要求しても動画ページは許可されません。拡張機能の再読み込み後は、もう一度要求してください。機密情報を除いた具体的な理由は失敗詳細に保存されます。録画が開始されなかった場合、保存されたのは時間範囲の記録だけです。 |
| 出力ディレクトリが正しくない | 実際に最優先となるディレクトリと、現在の OS ユーザーの権限を確認します。同じ場所を 2 か所で設定する必要はありません。 |

拡張機能の削除やブラウザーデータの消去は、ローカル資料に影響します。新しい profile に移る前にバックアップをエクスポートし、添付ファイルのバイト列が含まれているか確認してください。メタデータだけのバックアップでは、画像や録画ファイルを復元できません。外部 Agent が生成した成果物は、拡張機能の添付ファイルバックアップには含まれません。
