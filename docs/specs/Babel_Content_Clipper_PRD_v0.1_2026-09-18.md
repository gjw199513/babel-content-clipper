# 01. 产品身份与系列关系

## 1.1 正式名称

**【已确认】英文名称：Babel Content Clipper。中文名称：巴别塔片段采集器。** 仓库名、目录名和 MCP 服务标识统一使用 `babel-content-clipper`。界面中可以简称“片段采集器”，正式安装名称和文档标题保留 Babel 前缀。

Content 表示处理对象不限于视频或文章；Clipper 表示由用户主动圈出一部分内容。该名称不暗示自动抓取全部内容，也不把产品局限为视频笔记、电子书批注或 AI 总结服务。MCP 和“浏览器扩展”是能力与产品形态说明，不需要继续叠加到主品牌名中。

## 1.2 与其他 Babel 模块的分工

| 模块 | 用户的起点 | 主要职责 |
|---|---|---|
| 前序 AI 对话 MCP 插件 | 我要与一个或多个 AI 交流 | 提问、对话与回复交接；本 PRD 不擅自更改它的已定名称 |
| Babel Content Downloader／巴别塔内容下载器 | 我知道这个链接值得获取 | 获取已适配内容对象的文案、图片或音视频等 |
| Babel Content Clipper／巴别塔片段采集器 | 我正在阅读或观看，这一部分值得留下 | 记录用户选区、保存易丢失现场、提供待处理清单与处理历史 |
| 后续内容工作台、DSH 插件或助教系统 | 我已经拿到了素材，准备理解和使用 | 转录、识别、整理、练习、反馈及其他后续处理 |

三个插件可以共享底层通信、素材格式或执行工具，但必须能够独立部署和独立使用。Clipper 不要求先安装 Downloader；Downloader 可以作为 Agent 的一个获取工具，而不是每次采集必须走完的前置业务流程。后续 DSH 适配复用标准记录和 MCP 契约，不要求把 Clipper 先做成 DSH 专属插件。

## 1.3 核心问题

用户在阅读过程中做出了“这一段重要”的判断，但把这个判断变成可供 Agent 使用的内容，仍需复制文字、记地址、记时间、截图、下载和命名。素材容易散落，原内容位置容易丢失，换一个 Agent 后也不知道哪些内容已经处理。

Clipper 负责把这个判断保存成稳定、可处理的记录。产品不替用户判断内容重要性，也不把生成一篇总结当作采集成功。学习是重要场景，但产品本体是通用素材收集器。

# 02. 最终需求基线与不可破坏原则

以下规则是后续设计、代码生成和验收时的首要依据。

| 编号 | 已确认要求 | 实现约束 |
|---|---|---|
| B-01 | 必须是浏览器插件 | 本地伴随组件可用于 MCP 与文件交接，但不能把主要入口改成桌面软件 |
| B-02 | 面向用户主动选择的片段 | 不默认抓整站、整本书或完整视频，也不后台判断重要片段 |
| B-03 | 不限视频 | 支持文字、图片、图文区域、音频、视频和在线阅读内容的采集路径 |
| B-04 | 音视频同一操作切换起止 | 第一次开始、第二次结束；不预测选区长度 |
| B-05 | 前后预留可配置 | 示例为前 10 秒、后 10 秒，参数可为零或其他值 |
| B-06 | 真实点与预留范围同时保存 | 不能以扩展后的范围覆盖真实点击点 |
| B-07 | 获取范围与最终输出范围独立 | 允许多取；最终是否保留预留部分由执行参数决定 |
| B-08 | 优先获取源内容 | 可以直接取片段，也允许临时取得更大范围或完整文件后裁切 |
| B-09 | 浏览器录制是现场兜底 | 已经过去且没有录下来的现场，不能在下载失败后凭空补录 |
| B-10 | 不做内容理解 | ASR、OCR、摘要、语义判断、知识卡片和学习反馈不属于本插件 |
| B-11 | 默认先记录，后交给 Agent 处理 | 不把所有下载器、剪辑器和依赖安装器装进扩展 |
| B-12 | 支持用户主动查询待办 | 换 Agent 或换会话后仍读取同一份记录，不依赖聊天记忆 |
| B-13 | 支持到时提醒 | 可按无新增采集阈值合并提醒，示例 5 或 10 分钟；不持续调用模型轮询 |
| B-14 | 提醒不等于执行授权 | 用户确认或明确发出处理指令后才执行；单纯查询不执行 |
| B-15 | 不管理 Agent 会话 | 不要求同一会话，不实现逐个客户端的聊天注入或续聊适配 |
| B-16 | 主存储是扩展 IndexedDB | 不写当前网站的 IndexedDB，不建立强制云端数据库 |
| B-17 | MCP 支持读和回写 | 回写处理状态、执行结果及产物信息，作为统一记录依据 |
| B-18 | 历史不覆盖 | 真实采集事实、历次最终结果不被后续执行改写 |
| B-19 | 重新处理有独立入口 | 产生新的执行记录，不把旧成功结果重置成未处理 |
| B-20 | 用户可有意重复采集 | 不因为网址或选区相同而禁止再次记录；防的是误重复执行 |
| B-21 | 完成后不自动清理 | 历史可查看，用户可在插件或通过 MCP 主动清理已处理记录 |
| B-22 | 列表是简略预览 | 按具体内容标题、真实时间段、截断文字和可选小图显示 |
| B-23 | 快捷键与右键优先 | 不强迫每次打开面板，不抢占阅读器已有选择和翻页操作 |
| B-24 | 通用能力优先，适配补充 | 不承诺所有平台都能取源；通用选区、截图与有限平台适配组合 |
| B-25 | 原始数据与处理成品分离 | 记录主库以结构化数据为主，视频等大文件放在受控附件或输出目录 |

建议实现可以调整代码组织和技术选型，不能以“实现方便”为由恢复强制自动执行、整页抓取、同会话绑定或覆盖历史等已否定方案。

# 03. 使用对象、目标与范围

## 3.1 主要使用对象

目标用户是在浏览器中阅读文章、看视频、听音频、读电子书，并使用本地或具备文件访问能力的 Agent 处理素材的人。用户不需要了解媒体编码、MCP 消息格式、Cookie 或剪切命令。开发者和重度 Agent 用户可以通过标准 JSON、MCP 工具与执行 Skill 扩展流程。

未连接任何 Agent 时，扩展仍能完成标记、原文保存、截图、记录查看和导出。连接 Agent 是后续执行能力，不是使用采集功能的前提。

## 3.2 产品目标

目标一是降低从“值得留”到“留下可用记录”的操作成本。文字一般选中后一次操作；音视频一次开始、一次结束；不强制写笔记或解释理由。

目标二是保留原内容与来源，减少插件预先丢弃信息。视频默认可交付包含声音与连续画面的片段，图片为辅助或用户指定产物；只拿到截图时应明确标注。

目标三是让后续 Agent 精确知道需要处理什么，以及哪些已经处理。查询、执行、结果回写与重做都基于独立于会话的持久化记录。

目标四是保持轻量、可组合、低维护。借用浏览器原生能力和成熟执行工具，不建设通用 Agent 编排平台、云端知识库或完整编辑器。

## 3.3 首期范围与分步交付

【建议实现】先验证桌面 Chromium 浏览器上的闭环，再扩展其他浏览器。Chrome 与 Edge 可作为首批候选，macOS 与 Windows 作为本地桥和执行端验证环境；这属于建议的工程顺序，不是“只支持某一个内容平台”的产品限制。

首期产品范围包含基础文字/图片/区域采集、标准媒体起止记录、双范围时间、IndexedDB、列表与清理、MCP 查询与回写、导出、轻量提醒，以及明确授权下的现场保存路径。在线阅读器和少量公开视频平台用于代表性适配测试，不将所有特有接口塞进通用核心。

最小闭环和完整首期可以分开里程碑，但不能把尚未完成的现场音频、电子书或回写能力写成已经发布。第 24 章给出分步交付与真实能力披露要求。

## 3.4 明确不做

不做自动总结、转写、OCR、知识问答、全文推荐、语义关键帧判断或自动批注。读取页面已有字幕属于保存已有文字；把声音变为字幕不属于本插件。

不做整站爬虫、通用下载器、整本书批量复制、付费墙或 DRM 绕过。用户有权访问的内容也需要遵守相应平台和内容使用条件；首批测试优先使用公开免费或明确获授权的素材。

不做账户体系、支付、强制云同步、跨设备数据一致性、远程任务集群、多 Agent 会话编排或按客户端维护聊天线程。远程 Agent 的文件交接作为后续扩展，不假装本地路径天然跨机器可用。

# 04. 术语、内容对象与职责划分

## 4.1 关键术语

| 术语 | 定义 |
|---|---|
| 来源对象 Source | 被用户实际标记的文章、某个视频、某章电子书或页面区域，不等于全部浏览历史 |
| 采集记录 Capture | 一次用户主动操作形成的事实记录，含原文或选区、来源、真实切点及参数快照 |
| 待处理工作项 Job | 针对一条采集记录或一组记录的执行请求；重新处理会创建新的工作项 |
| 执行结果 Result | 某次工作项完成或失败后的不可覆盖结果，含产物、范围、方法和验证信息 |
| 原选区 Original Selection | 用户真实开始和结束操作对应的内容范围 |
| 扩展获取范围 Padded Range | 在原选区前后增加配置余量后的计划获取范围 |
| 实际获取范围 Acquired Range | 工具实际取得并经验证覆盖的源内容范围 |
| 最终输出范围 Output Range | 成品中保留的内容范围，可以不同于获取范围 |
| 现场素材 Captured Asset | 当时保存的文字、图片、区域截图或音画录制 |
| 历史归档 History | 对已完成记录与历次执行的查看方式，不等于删除、迁移到云端或改变原事实 |

## 4.2 “原始”需要准确表达

本产品优先保存网站实际提供且用户有权取得的原文、图片或媒体资源。这里的源媒体不承诺等同于作者上传前的母版。

获取网站音视频资源、录下浏览器播放输出、对录制进行速度校正，是三种不同情况。结果中分别标注 `source_media`、`browser_recording`、`normalized_recording`，不能统称“无损原视频”。截图也应区分 `source_image`、`decoded_frame` 与 `screen_region`。

原选区、记录参数、处理策略和最终结果要能关联，但相互不覆盖。页面或服务器后续改变同一个 URL 的内容时，保留最初的标题与身份快照；新解析结果作为本次执行信息追加。

## 4.3 四层职责

浏览器扩展负责用户交互、页面读取、来源与时间定位、即时附件、记录 UI 和主数据库。本地桥/MCP 负责受控读写、数据交接、能力报告与可选的资源更新通知。用户 Agent 负责理解明确的处理指令、选择执行工具、检查环境、取源和后处理。后续系统负责理解素材、学习与内容生产。

扩展与桥之间共享契约，不共享网站业务状态；执行器可换而记录仍然有效。前两个产品的下载内核或本地桥可以复用，但不能强制绑定整个产品流程。

# 05. 端到端用户流程

## 5.1 网页文字即时留下

用户用原网页的方式选择一段文字，通过快捷键或右键点击“收集选中文字”。扩展当场保存完整原文、标题、来源、选区上下文和可用的位置标识，给出不抢焦点的成功反馈。列表只显示短预览，但详情与 MCP 返回完整内容。

用户随后可以继续阅读，也可以在任意已接入 MCP 的 Agent 中询问“有哪些待处理的内容”。文字已经保存，不应为了处理而再次抓整篇文章；Agent 可以读取原文并按用户指令导出。是否用于总结由用户在后续系统决定。

## 5.2 视频片段延后处理

用户在视频 10:00 开始，在 12:00 结束。扩展保存原选区，并记录前后各 10 秒的预留参数。默认标记完成不下载完整视频；列表显示 10:00—12:00 和“待处理”。

用户说“把这个视频的两个片段处理一下”，Agent 查询详情，登记本次工作项，按源媒体优先的策略获取。可取 09:50—12:10，再根据用户要求裁成 10:00—12:00，或保留预留部分。结果和文件位置回写扩展，记录进入历史。

## 5.3 闲置提醒后再执行

最后一次完成或新增采集后，达到配置的无新增阈值，扩展合并提醒“该来源有若干条待处理”。提醒不启动下载。用户可以忽略、稍后处理、主动进入任意 Agent 查询，或者在客户端支持的交互中确认。

不要求向当前聊天插话，不要求反向创建新会话。客户端不支持 MCP 资源通知时，插件内提醒和主动查询仍然可用。

## 5.4 原生阅读器批注与 Babel 并行

用户在在线电子书内选文，原阅读器仍可显示“划线、笔记、复制”等菜单。用户触发 Babel 快捷键时，只读取这次选择，不接管原菜单、不自动复制全部批注。若原阅读器清空浏览器选区，通过有效快照或适配器获取；无法获取时，明确提供复制导入或区域截图。

## 5.5 现场录制

对不宜延后获取的动态内容，用户明确启用“标记并保存现场”。开始操作同时启动允许范围的音画录制，结束时封存现场附件。后续仍可优先取源；取源失败时使用已经录下的文件，并标记其捕获方式、声音轨和时间覆盖情况。

## 5.6 重新处理与再次采集

用户可以对历史记录要求“重新处理，这次不要前后预留”。系统创建新工作项和新结果，第一次结果保留。用户也可以再次手工采集同样的片段，产生新的 Capture；相似提示不能阻止明确的再次记录。

## 5.7 手动清理

用户在列表中选择一条、一个来源或全部已处理记录，看到将清理的数量与范围。确认后删除插件内相应记录、执行历史及无其他引用的内部预览；默认不删除执行输出目录中的视频和图片。MCP 清理调用遵守相同规则。

# 06. 快捷键、右键与低干扰交互

## 6.1 主要交互入口

【已确认】快捷键和右键至少提供可用入口。建议同时实现：快捷键承接连续阅读过程，右键承接明确对象，面板用于查看、修改执行参数和管理记录。默认不做选文即弹出的第二套浮动工具栏。

浏览器 `commands` API 支持扩展命令与用户重绑定；`contextMenus` 支持 selection、image、video、audio 等上下文。[R02][R03] 具体快捷键组合应经过冲突测试，不能承诺任意系统都有效。

| 动作 | 建议命令 | 建议初始快捷键 |
|---|---|---|
| 收集当前文字或图文选区 | `capture-selection` | Alt+Shift+S |
| 开始/结束音视频区间 | `toggle-media-capture` | Alt+Shift+V |
| 框选当前可见区域 | `capture-region` | Alt+Shift+X |
| 打开记录列表 | `open-library` | 可不设默认，由用户配置 |

以上为可调整建议；macOS 需要检查对应 Option/Command 行为。不要占用复制、粘贴、空格播放、左右翻页等常用操作。系统快捷键或其他扩展冲突时显示实际绑定状态，并引导到浏览器快捷键设置页。[R03]

## 6.2 右键菜单规则

选择文字时显示“收集选中文字”；右键图片时显示“收集图片”；右键音视频时显示“开始记录片段”或“结束记录片段”；通用页面可提供“框选截图”和“打开采集记录”。菜单不替换原浏览器菜单，也不强行解除网站的原有事件策略。

右键事件中的选中文字、媒体资源地址及框架信息作为本次操作上下文。若网站的自定义菜单阻止原生右键可达，快捷键和扩展面板是兼容入口，不以注入侵入式代码作为默认解决方式。[R02]

## 6.3 状态反馈

第一次媒体操作后，图标徽标或轻提示显示“记录中”；结束后显示“区间已保存”。现场录制应额外显示“正在录制”，不能把仅记录时间的位置状态与录制状态混淆。

普通文字和图片采集完成后短提示即可，不抢焦点、不暂停播放器、不弹出强制编辑器。存在失败时必须明确说明：未取得选区、未取得图片、未能持久保存、录制权限被拒等，不能统一显示成功。

## 6.4 误触与输入框

【建议实现】对快捷键长按产生的重复命令做短时间防抖，但不能把用户正常的开始/结束操作吞掉。处于可编辑输入框、密码框或受保护字段时，不主动读整段输入内容；仅在明确支持并且用户主动选择时采集普通编辑内容，密码与敏感输入默认排除。

区域截图模式可以用 Escape 取消；取消只结束这次框选，不取消其他已经保存的记录。媒体记录的异常取消需要保留已发生的开始事实，并标记中断，而不是伪造正常结束点。

# 07. 文字、图片与页面区域采集

## 7.1 DOM 和选区读取是基础路径

内容脚本可以读取页面 DOM 并通过扩展消息传递给后台；它运行在隔离环境中，不天然拥有页面脚本的内部变量。[R01] 普通网页直接读取当前内容，不另开一个爬虫重新抓全文，也不让模型控制浏览器猜选区。

文字采集依次使用本次右键事件的有效选择、当前文档 Selection/Range，以及经过有效性验证的短期选择快照。图文片段可通过 `Range.cloneContents()` 取得选中部分的结构；这不代表直接把未经清理的 HTML 注入扩展。[R12][R13]

## 7.2 文字数据要求

保存完整选文、来源标题与地址、采集时间、选区前后少量文本、可用章节信息和定位方式。保留用户所选内容的顺序和换行；为展示而生成的截断预览不能覆盖原文。富文本保存是附加格式，不是强制所有记录都生成 HTML。

参考 W3C TextQuoteSelector，用 exact、prefix、suffix 辅助定位；可增加 TextPositionSelector 或局部节点线索，但不能承诺网页重排后一定精确恢复。[R18] 所有定位信息只是对已选内容的补充，不默认扩展为整篇正文。

## 7.3 HTML 与图文区域

对混合选择，保存文字与允许的 HTML 结构，提取选区内关联图片与链接；已取得的附件和仅取得地址的资源分别标记。图片失败不应让已经取得的文字消失，允许“部分采集”。

HTML 预览过滤脚本、事件属性、危险协议与主动加载内容；可以评估 DOMPurify 等成熟清理器。[R58] 不把页面内所有样式、追踪脚本和隐藏数据作为“保真”附带保存。需要局部视觉保真时，增加用户选择区域的截图。

## 7.4 图片保存

优先保存用户明确点中的实际资源，记录资源地址、尺寸、格式及来源。无法直接获取时可以保存待获取引用，或在用户选择后改用区域截图。资源请求仍受身份、来源和浏览器权限影响，不能仅凭拿到 URL 就显示“原图已保存”。

屏幕区域截图保存可见像素及裁切矩形、视口、缩放与设备像素比等必要映射信息，类型标记为 screen_region。跨域媒体画到 Canvas 后可能无法读取像素，不能把 Canvas 截帧当作所有站点通用的原图提取方式。[R10][R26]

## 7.5 原生复制与剪贴板兼容

提供显式的“从剪贴板收集”或粘贴导入入口，不监视所有复制动作。剪贴板读取存在权限和执行环境限制，需要用户触发并在适合的扩展上下文完成。[R17]

无法确定剪贴板内容来源时，标记来源未知或由用户补充；不能自动把当前网页当作来源。用户只是使用原阅读器的复制功能，不等于已经授权把剪贴板写入 Clipper。

# 08. 音视频单键起止与目标锁定

## 8.1 基本状态机

同一个媒体采集操作第一次记录开始，第二次记录结束。第一次操作立即将开始点和来源写入 IndexedDB；第二次补齐结束点后封存这次采集。操作对应的是媒体内容的位置，不是预计观看时长。

不提供默认“推测刚才重要的 30 秒”作为主交互，也不因为无新增十分钟而替用户结束未完成区间。用户明确提出的前后预留已覆盖点击不准的主要问题。

## 8.2 目标选择

右键点中媒体时优先使用对应媒体元素。快捷键时可以选择当前明确活跃且可识别的主播放器；若多个候选无法可靠区分，提示用户选择目标。开始后锁定内容身份、元素/框架引用和文档实例，结束操作不能切换到广告、小窗或其他标签页。

【建议实现】每个标签页默认只允许一个未结束媒体区间。不同标签页的状态分别保存；不实现并行现场录制调度。用户在另一个标签页按快捷键，只操作当前标签页的目标，不暗中终止其他页面。

## 8.3 暂停、跳转和内容切换

暂停期间继续保存记录状态，媒体时间不增加。变速时记录速度变化，但不修改已经保存的点击位置。跳转时必须留下时间不连续的信息，不用最小起点和最大终点自动覆盖所有未观看区间。

【建议实现】将同一次起止之间的连续观看段保存为 segments；向前跳转会产生区间缺口，向后回看会产生重复或重叠段。执行策略可以选择按这些区间取源，或由用户明确覆盖为一个连续区间，但保留原事件和原区间。

关闭页面、页面卸载、播放器被替换或内容身份变化时，不能把最后观察时间伪装成用户第二次点击。记录 `interrupted` 和 `last_observed_media_time`，允许用户后续补充执行范围；原本缺少结束点击的事实仍保留。

## 8.4 采集对象是媒体本体还是页面现场

用户选媒体片段时，以媒体声音和画面为主要目标；用户框选整个动态页面时，页面上的字幕、图表、弹窗或演示布局也可能是目标。后者不能因为后来取得了一个视频源文件，就删除具有额外信息的现场素材。

单帧保存是辅助操作，不替代连续片段。连续视频与音频可由执行端分离或重新封装；是否仅输出图片由用户在执行参数中决定，而不是插件自动判断。

# 09. 真实切点、预留范围与倍速时间轴

## 9.1 必须同时保存的范围

记录用户真实切点 `[s,e]`、前后预留 `pre/post`，以及计划扩展范围。若已知源时长为 `D`，计划获取范围为：

```text
planned_start = max(0, s - pre)
planned_end   = min(D, e + post)
```

D 未知时不假造视频总长，先保存未夹紧的结束请求并在获取阶段确定边界。预留不足不报采集失败；分别记录请求值、实际可用值及边界原因。

| 信息 | 示例 |
|---|---|
| 用户真实点击 | 10:00 开始，12:00 结束 |
| 参数快照 | 前 10 秒，后 10 秒 |
| 计划获取 | 09:50—12:10 |
| 实际获取 | 例如因分片边界取到 09:48—12:12 |
| 最终输出 | 10:00—12:00，或按授权保留预留 |

下载器只允许按分片或关键帧定位时，实际获取可宽于计划；不能因此改变原始选区。最终结果同时报告 requested、acquired、output 三类范围及偏差。

## 9.2 预留参数的不可变快照

开始采集时或结束封存时形成明确的参数快照，建议同一记录以开始时设置为准。用户后来修改全局默认值，只影响新记录。历史记录中的真实点和旧参数不覆盖。

用户需要改变处理范围时，提交本次执行的 overrides，或复制生成新的派生记录，指向原 capture_id。前一次执行参数和结果保持不变。未封存的采集草稿可以补齐结束事件，但封存后不提供无痕编辑原历史的接口。

## 9.3 倍速

普通播放器的 `currentTime` 表示媒体位置，`playbackRate` 表示播放速度。[R14][R15] 用户两倍速看完原视频 10:00—12:00，原区间仍是两分钟，现实经过一分钟不改变它。

源媒体获取按源时间裁切，不需要先录倍速音频再恢复。现场录制得到的是实际播放输出；可以另做速度校正版，但不能保证重建成原始音轨。保留原录制，处理方法与速度映射写入结果，不用校正版覆盖原件。

媒体时间、采集开始后的经过时间以及 UTC 采集时间分别保存。逐帧回调可提供媒体时间信息作为图片定位的补充，但适用性需按浏览器验证。[R16] 原时间轴未知时使用 null 和原因，不用播放墙钟时间猜原始切点。

## 9.4 连续性与图片时间戳

每张导出的图片记录源时间或明确的录制时间；文件内时间为 0 的片段也必须映射回原媒体位置。多段拼接输出需保存输出时间到各源区间的映射，不能只保存单一偏移。

第一版不强求逐帧无误差，但要求结果诚实报告精度、起止偏差、关键帧调整和是否重编码。用户主动标记的一帧优先保留；固定间隔抽帧是可选技术参数，不进行 AI 关键帧识别。

# 10. 在线电子书、PDF 与阅读器兼容

## 10.1 不接管阅读器

【已确认】Babel 沿用用户原来的选择行为，不替换阅读器的划线、批注、复制、翻页和快捷键。选文自动出现在原阅读器菜单里，不等于应该自动采集；必须有 Babel 的明确触发动作。

默认不向正文插入永久高亮标签，不重写段落结构，不在每次选择时显示另一套浮窗，不强制取消原菜单。用户使用原阅读器“添加批注”时不自动同步全部批注；未来若提供专门导入，应是单独授权功能。

## 10.2 标准选区与最近有效快照

第一层读取当前选择或本次原生右键事件提供的选文。若选择因点击菜单而消失，可使用最近一次有效选区快照。快照只在当前已获权限的页面中短暂存在；没有 Babel 采集动作，不持久写入，不跨页面累计用户选择历史。

快照至少关联 document 实例、frame、页面/章节身份、选文、选区位置和产生时间。导航、换章、目标内容变化或明确新选择时失效。选区为空不能机械地退回上一次非空值，否则容易把上一章内容保存成当前选择。

【需实测】选择事件的时序、页面清空选区以及 content script 首次注入时机。仅在按快捷键后才注入脚本的页面，不一定来得及取得此前已经消失的选区；需要按站点授权提前启用适配器，或提供原生复制入口，不能为此默认读取所有网站内容。[R01][R12]

## 10.3 EPUB 与自定义阅读器

EPUB.js 官方示例展示了 selected 事件、CFI 范围和读取对应文字，并会在处理后清空浏览器选择。这说明普通 getSelection 并非所有阅读器的充分方案。[R20][R21]

适配器在有权限且阅读器提供可用接口时取得当前章节、选区文本和 CFI；不能因为网站用了 EPUB.js，就假定内部实例一定暴露在全局。跨 iframe 读取需按框架 URL 和权限注入，页面对象访问还需考虑隔离环境。[R01]

电子书位置可以借鉴 Readium Locator，保存书名、章节标题、资源 href、进度或片段定位，以及选文上下文。[R19] 页码只作辅助，因为重排、字体和窗口变化可能使显示页数变化。书名、章节和定位失败时分别为空并标注，不凭推断编造。

## 10.4 PDF

网页嵌入 PDF 阅读器若存在可访问文本层，优先沿用用户选区，并保存页码及可用区域信息。需要解析用户有权访问的 PDF 文件时，可参考 PDF.js 的页面文本读取接口；取得页文本后仍需映射回用户的具体选区，不自动扩大为整页或整份文件。[R22][R23]

浏览器内置 PDF 查看器及其他扩展页面不能一概视为普通网页，注入能力需实测。基础降级路径为原生选择/复制、显式粘贴导入或可用的区域截图。不为兼容 PDF 首先建设一个完整 PDF 编辑器。

## 10.5 Canvas、图片式页面与封闭渲染

Canvas 是位图绘制表面，不天然提供其中字符的 DOM 文本结构。[R24] 对图片式电子书、Canvas 阅读器、封闭组件等，按顺序检查合法可用的阅读器接口、原生复制和截图能力。

只有截图时保存图片，标注“未取得文字”。不执行 OCR，不因界面看起来是文字就伪报成功。原文访问受限制时不解除 DRM、不绕过授权，也不强制注入破解代码。

## 10.6 首批阅读测试夹具

建议建立自有普通 HTML 文章、同源和跨源 iframe、EPUB.js 示例阅读器、PDF.js 示例、Canvas 文本演示与具有自定义划词菜单的测试页面。用这些可控样本验证通用层，再补真实平台适配。只有通过测试的能力才进入发布支持清单。

验收核心是原交互不被改变，选文和来源不串，失败可解释。不能把“页面里能打开一本书”当作“能可靠采集其任意选区”。

# 11. 主动查询、闲置提醒与用户授权

## 11.1 两种入口，共用同一份待办

用户可以主动询问“有哪些待处理的视频或文字”“把今天标记的这些片段处理一下”。Agent 通过标准 MCP 工具查询统一记录，不需要指定聊天会话。用户也可以在插件里选择待处理项并复制任务说明或使用客户端已有的 MCP 操作能力。

扩展可在满足提醒规则后提示有新记录。两种入口读取同一数据库，不各建一份队列。主动查询在记录封存后立即可用，不用等待闲置阈值；未结束区间可以查询，但不能作为完整区间直接执行。

## 11.2 查询、提醒与执行分离

| 表达或事件 | 允许行为 |
|---|---|
| “有没有待处理的内容？” | 只查询、展示，不领取、不下载 |
| “处理这两个片段”且目标明确 | 属于明确执行请求，可在已有权限范围内领取和处理 |
| 无新增达到阈值 | 只产生提醒，不安装工具、不取源 |
| 用户未回应提醒 | 留在待办，不默认同意、不反复催促 |
| “重新处理上次的记录” | 走独立重处理接口，保留旧结果 |
| “清理全部已处理记录” | 按明确范围执行记录清理，不连带删除成品 |

不强制所有主动处理指令都再次询问一遍。需要额外授权的安装、登录、目录访问等仍按执行环境要求确认，不能把处理指令扩展成无限系统权限。

## 11.3 闲置合批

【建议实现】默认阈值 10 分钟，允许 5 分钟、自定义或关闭。此默认值属于可调整设置，并非限制用户实际片段长度。

闲置定义为当前来源下没有新增或有效修改采集记录，不是没有鼠标键盘操作，也不是视频必须停止播放。每次相关采集更新重设一次性截止时间；浏览器的 alarms 可承担这种调度，但休眠、重启或后台调度可能导致延迟，因此只保证达到条件后合理触发，不承诺精确到秒。[R06]

仅在存在新的可处理内容时提醒。相同记录集合及版本只提醒一次；用户未回应不重复发送。新记录形成新版本后可再次合并提醒。已处理内容不因再次打开页面而重入提醒队列。

录制或未结束区间不因闲置自动结束。当前来源已经有完成的记录但仍有开放区间时，建议暂缓该来源的批次提醒，界面保留“记录中”；主动查询可以只选择已经结束的记录。

## 11.4 其他提醒条件

即时提醒、播放结束、关闭或离开当前内容、用户手动整理，可作为可选事件。它们只改变何时提示，不改变授权规则。播放结束不能等同于第二次点击；用户忘记结束的记录保持中断或待完善状态。

关闭标签页前记录应已逐次落库，关闭事件仅用于提醒或标注生命周期。整个浏览器退出时，不保证 MCP 继续读取主库；恢复后补检查待办和未发提醒，不根据断线期间的猜测自动执行。

## 11.5 MCP 通知能力边界

MCP 支持资源读取及与客户端能力协商相关的更新通知；协议通知不是通用聊天消息注入，更不保证唤醒模型开始一轮任务。[R28][R29] Elicitation 可在适用请求交互中向用户索取输入，但也不是对任意空闲客户端持续推送确认框的保证。[R30]

因此首版稳定路径是 MCP 工具主动查询，加插件内提醒；支持标准订阅/资源更新的客户端使用增强通知。具体方法名以协商的协议版本为准，不硬编码成所有客户端都必须支持同一种机制。

不实现 Codex App Server、OpenClaw hooks 等专属会话启动适配，不维护 thread_id 或 session_key，不为等待阈值挂起一个长期工具调用，也不持续让模型轮询。

# 12. 记录列表、详情、历史与清理界面

## 12.1 信息架构

【建议实现】工具栏弹出页承担当前状态和常用入口；记录列表使用扩展页或侧栏；设置页负责快捷键、预留、提醒、MCP 连接与存储信息。形态可在原型中选择，但数据和操作规则一致。

列表主要视图为“待处理”“历史”“全部”。按来源标题归组，展示站点/书名章节、记录时间、条数和处理进度。使用具体内容标题，而不是只写网站名称；标题缺失时显示合理占位和域名，不能由 AI 自动编造标题。

## 12.2 列表样例

```text
从服务拆分到系统架构设计
bilibili.com · 3 条记录 · 2 条已处理 / 1 条待处理

[视频] 10:00—12:00                         已处理
[视频] 18:35—19:20                         待处理
[文字] 系统拆分并不意味着职责已经清晰……     已处理
```

文字预览只做长度截断，不做语义摘要。视频显示真实区间；前后预留、实际获取与输出范围放进详情。图片有已取得的缩略图就显示；没有则用类型图标。不得为生成列表预览启动整段下载、额外模型调用或重型视频处理。

标题是显示属性，不是唯一键。同名内容、同 URL 下不同章节、同一视频中的多次选区和用户有意重复采集必须能够区分。

## 12.3 详情页

详情展示完整原文或现有附件、来源、采集时间、实际操作点、预留快照、区间连续性、当前工作项、历次结果、失败原因和产物位置。能打开原位置时提供链接；不能精确跳回时仅打开原来源并说明定位能力。

支持查看新旧执行参数差异，不提供覆盖原历史的“直接改掉旧切点”。需要调整时形成新的执行覆盖参数，或复制出新采集记录。

## 12.4 空、错与连接状态

无记录显示采集入口；有记录但没有待办显示可查看历史；MCP 桥未连接显示“本地记录可用，Agent 连接未建立”。数据库不可访问与真正空列表必须区分。

图片或产物路径失效显示“文件当前不可用”，不删除成功执行的历史事实，也不显示为从未处理。已采集部分内容但缺少音轨/附件的记录标记“部分”，方便用户判断。

## 12.5 清理交互

提供清理单条/所选、当前来源下已处理、全部已处理。批量操作显示将删除多少条记录、多少次执行，以及会保留多少待办。用户可先导出，但不把导出做成强制前置。

默认清理成功完成且没有活跃工作项的记录，失败和部分成功是否纳入由显式范围决定。一个来源下只删已处理条目，仍有待办就保留来源组。处理中记录不直接删除，先停止或等待后再清理。

提示文案应明确：清理插件记录与其专属预览，不删除外部输出目录的素材文件。确认一次即可，不把“一键清理”做成多层重复弹窗。MCP 清理与界面使用相同业务服务和保护规则。

# 13. 扩展 IndexedDB 与数据模型

## 13.1 单一主存储

【已确认】主数据存放在扩展自身 origin 的 IndexedDB。内容脚本把采集请求发送到扩展受控上下文，由统一存储模块写库。不要从目标网页直接调用其 IndexedDB 保存 Babel 记录。Chrome 文档区分扩展页面与内容脚本所在页面的存储上下文。[R04]

数据库以 JSON 兼容结构化记录为主，不必为了小数据建立外部数据库服务。本地 JSON 用于导入导出、备份和协议调试，不与 IndexedDB 形成两个长期相互覆盖的主库。

文字和元数据通常比音视频小，但不承诺容量无限。附件、缩略图、错误日志和导入包都可能占空间，需要显示实际使用量。卸载扩展、删除浏览器配置、用户清站点/扩展数据等操作不属于“自动保留”保证，需提供导出备份说明。[R04]

## 13.2 建议对象存储

以下为逻辑划分，开发时可以合并对象存储，但不得丢失不覆盖历史与原子领取语义。

| 存储 | 作用 | 可变规则 |
|---|---|---|
| `captures` | 来源快照、选文/区间、预留、封存标志 | 草稿允许补齐事件；封存后事实不覆盖 |
| `jobs` | 待办、处理中状态、领取者、执行参数 | 当前工作状态可变；每次重处理新建 job |
| `execution_events` | 开始、进度、异常、回写等事件 | 追加事件，不覆盖历史事件 |
| `results` | 每次最终结果、产物和验证报告 | 终态不可覆盖；冲突返回错误 |
| `attachments` | 小附件或受控文件引用、完整性信息 | 原附件不被派生件替换，清理按引用关系 |
| `settings` | 快捷键显示、预留默认、提醒与权限设置 | 更新设置不改变历史快照 |
| `dedupe_receipts` | 有限的请求幂等凭据 | 仅记录防重复所需标识，不保存多余正文 |

建议为 capture_id、job_id、status、source_key、created_at 建索引。列表只取预览与分页结果，详情再取全文与附件；大型 Blob 不随每次查询加载。可以评估轻量 idb 包，也可直接封装原生 IndexedDB，不同时引入多套数据库框架。[R59]

## 13.3 采集记录字段

| 字段组 | 必须表达的信息 |
|---|---|
| 身份 | schema_version、capture_id、profile_id、kind、创建时间 |
| 来源快照 | 具体标题、原地址、可用规范地址、域名、内容标识、章节/框架信息 |
| 原始选择 | 完整文本、位置线索；或用户开始/结束点及连续区间 |
| 捕获参数 | pre/post 秒数、源时间轴类型、页面现场/媒体本体目标 |
| 现场事实 | 点击墙钟时间、速度变化、跳转、中断、可用时长 |
| 采集方法 | DOM、右键选文、阅读器接口、剪贴板、源图、截图、录制 |
| 已有附件 | asset_id、MIME、字节数、校验摘要或受控引用 |
| 完整性 | 完整/部分/待补充，以及不能取得的字段或轨道 |

未知值用 null 和明确原因，不以零代替未知时间，不以当前页面标题猜书名。临时 tab_id、frame_id、document_id 只帮助当前操作，不能作为跨重启的内容唯一身份。

## 13.4 持久化与消息确认

每次开始、结束、文字保存、领取、结果回写都必须在相应 IndexedDB 事务成功后才返回成功。后台 service worker 可能终止，内存状态不能成为唯一依据。[R05]

采集请求包含 request_id；同一点击因消息重试到达两次时，返回原 capture_id，不能新增两条。用户再次主动点击形成新 request_id，允许相同内容的第二条记录。

MCP 回写必须得到扩展事务完成的 ACK，才能向 Agent 返回“已记录结果”。如果浏览器退出，返回 `BROWSER_UNAVAILABLE` 或 `WRITEBACK_PENDING`。可由执行端保存最小待回写结果收据，下次重连重放；这不是第二个业务主库，更不能在没有 ACK 时显示已经更新历史。

## 13.5 导入、迁移与清理

导出包含 schema_version 和完整关系。导入必须校验格式、引用、尺寸和安全字段；相同 ID 且内容一致可跳过，相同 ID 内容不同不能静默覆盖，应报告冲突或显式导入为新记录。

版本迁移以事务执行并验证，失败不得清空旧库后假装升级成功。只改变数据表示时保持语义和原事件不变。清理仅删除用户授权范围及不再被引用的内部附件，不能通过历史迁移偷偷清掉旧结果。

# 14. 处理状态、防重复、归档与重新处理

## 14.1 记录与执行分开

“历史不改”不意味着界面不能从待处理更新成已完成。不可改的是封存的采集事实、事件和历次终态结果；当前状态是这些事实的投影，可以更新。用户可在历史中查看每次处理。

建议 Capture 的采集状态为 open、sealed、interrupted；Job 的当前状态为 pending、processing、completed、partial、failed、cancelled、uncertain。首次封存按需要创建初始待办；重新处理创建新的 Job。

即使文本已经当场保存，仍可有待交接/导出的初始 Job。仅 get_record 读取不自动标为已完成；用户明确要求后，Agent 以“原文已获取，无需再次下载”的处理结果结束工作项，避免长期待办与无意义重复爬取。

## 14.2 原子领取

查询不会改变状态。执行请求明确后，领取接口在一个事务中核对目标仍待处理并登记 job_id、claim_token、执行者和参数快照。两个客户端同时领取同一工作项，只有一个成功，另一个得到已被领取的信息。

批量领取可以逐项返回 accepted、already_claimed、not_eligible，不因一条失败就错误吞掉其他结果。执行器只处理成功领取的项目，未授权项不能顺带加入。

## 14.3 超时不等于可以立即重跑

【建议实现】记录心跳或租约用于识别可能失联，但租约过期并不能证明外部下载已经停止。先标记 uncertain，查询执行收据或请用户确认恢复，不自动把同一任务放回待办并启动第二份下载。

系统能够防止经过本接口领取与提交的误重复；不能保证控制一个绕过接口自行执行命令的外部 Agent。这个边界应写进执行 Skill，不能宣传“绝对不会重复”。

## 14.4 结果提交

结果包含 job_id、claim_token、结果请求幂等键、终态、实际参数、取得范围、输出范围、轨道情况、产物引用和验证信息。完全相同的重试提交返回已接受；对同一终态提交不同内容返回 `RESULT_CONFLICT`，不覆盖旧结果。

声称成功但缺少用户要求的声音、画面或片段覆盖时，记录 partial 或 failed。产物校验分清 `agent_reported` 和 `bridge_verified`；桥没有实际读取文件，就不能伪称已验证可播放。

## 14.5 重新处理

用户明确重做已完成、失败或部分完成的记录，通过独立接口创建新的 Job。原 job/result 不变，新执行保留 parent_job_id 或 reprocess_of 关系。调整 padding、输出格式或截帧间隔只属于新执行参数。

同样的内容再次手动采集属于新 Capture，而不是自动重处理。可以提示相似，但不阻止。普通 list pending 不自动把历史重新激活；存在明确新重处理 Job 时，它可以出现在待办并标记“重新处理”。

## 14.6 归档与手动删除

完成即进入历史视图，默认不自动物理删除。用户可以清理已完成、且没有新待办或活跃执行的整条记录；执行中和存在未处理后续工作的 Capture 不纳入一键清理已处理。

失败、部分成功、取消是否清理由明确筛选决定。清理已授权历史可以物理删除，不需要构建复杂回收站；但必须说明不可恢复和不包含外部成品删除。可保留不含正文的短期幂等墓碑防止迟到回写重新生成已删记录，期限与数据量受控，不以此隐蔽保留用户清理的内容。

# 15. MCP 接口与本地桥接契约

## 15.1 角色与连接方式

MCP 对外提供标准工具和可选资源。业务数据由扩展 IndexedDB 统一负责，外部客户端不能直接打开浏览器配置目录修改数据库。MCP 的资源与工具模型提供访问与调用机制，具体业务接口由本产品自行定义。[R28][R29]

【建议实现】采用 TypeScript 统一记录契约；本地桥可使用 Node.js 等轻量运行时。首版优先 stdio MCP 接入本机 Agent，通过受控本地 IPC 对接已经连接的扩展。Native Messaging 是可研究的正式扩展通信机制，需安装本地 host 并由扩展发起连接；不能把它误写成任意 Agent 可直接连接浏览器的公共端口。[R07]

一种可验证结构是：扩展连接 Native Host；Host 与本机 broker 共用或转接；Agent 启动的 MCP stdio 进程经本地 IPC 向 broker 发请求；最终由扩展读写 IndexedDB。必须解决多浏览器配置隔离、host 重启和连接路由，不默认不同进程共享同一内存。该部分做成一个小的连接原型后再锁定实现，不叠加第二套主数据库。

浏览器未运行时不能承诺查询扩展主库。MCP 返回连接错误和可恢复说明，不能返回空数组。打开浏览器和启动 Agent 的安排由用户控制，不自动新开聊天或偷偷启动录制。

## 15.2 建议最小工具集

工具前缀建议 `babel_clipper_`。表中均为自定义接口建议，可优化命名，但读、执行登记、回写、重做和清理应有清晰边界。

| 工具 | 职责 | 关键约束 |
|---|---|---|
| `list_records` | 按待办、历史、来源、日期分页查询 | 默认待处理；查询无副作用 |
| `get_record` | 读取完整原文、范围、附件引用和历史 | 不把查看当完成 |
| `read_attachment` | 读取或安全物化用户已保存附件 | 受大小、路径和权限限制 |
| `claim_records` | 按明确处理请求领取工作项 | 原子检查、幂等、防并发误领取 |
| `commit_result` | 回写本次终态结果 | ACK 后成功；不覆盖已有终态 |
| `reprocess_record` | 显式创建新的重处理工作项 | 不重置旧结果；返回新 job_id |
| `cleanup_records` | 预览并执行用户要求的记录清理 | 范围固定、保护活跃任务、不删外部成品 |

连接状态、能力查询和导出可作为小工具或资源补充，不必首版增加几十个接口。工具描述需注明读写性质，但协议中的提示性元信息不等于完整权限隔离；本地服务仍要执行权限与范围检查。[R29]

## 15.3 查询返回结构

```json
{
  "schema_version": "1.0",
  "profile_id": "profile_local_01",
  "records": [
    {
      "capture_id": "cap_demo_001",
      "job_id": "job_demo_001",
      "kind": "media_range",
      "title": "从服务拆分到系统架构设计",
      "preview": "10:00—12:00",
      "status": "pending",
      "assets_state": "location_only",
      "original_range": {"start": 600, "end": 720}
    }
  ],
  "next_cursor": null
}
```

`assets_state` 至少区分 location_only、partial_saved、saved；它与工作项是否完成是不同维度。列表默认仅返回简略文本，不把大附件编码塞入每次工具上下文。

## 15.4 执行领取与授权

建议领取参数包含 capture/job ID、execution_profile、请求幂等键和用户指令来源说明。执行配置包括取源优先、是否允许临时全量获取、padding 覆盖、最终保留策略、产物类型、输出目录权限和预算。

`user_request` 文本或 Agent 自报的 `approved=true` 不是独立可信的系统授权。读写能力必须受已建立的本地连接权限约束；高风险操作在插件 UI 或可信客户端确认流程中完成。查询和通知不能生成等价于用户同意的批准记录。

协议层不绑定任何会话。由实际 Agent 客户端在自己的用户交互中理解明确指令；本产品只校验被请求的记录与允许的执行动作。

## 15.5 回写协议与附件

源链接、私有令牌、操作系统路径和产物引用分开。大文件优先在用户允许的输出目录创建，通过受控 file reference 记录；确需把浏览器附件交给 Agent 时，返回真实 MIME 的内容或物化结果，不能只返回一个浏览器内部 asset_id 就说 Agent 已取得图片。

Native Messaging 等通道有消息大小和结构限制，应分块传小附件或使用受控本机文件通道，不能一次推完整长录屏。[R07] 远程客户端不能读取本机绝对路径时返回明确限制，不假造跨机器共享。

MCP 的图片/资源内容是否真正进入模型视觉上下文取决于宿主。执行工具能够读取文件与模型已经“看见”图片是两件事；本插件不对后者作无条件承诺。[R28][R29]

## 15.6 清理协议

建议同一 `cleanup_records` 工具有 preview 和 execute 两阶段。preview 返回具体可删除 ID、版本、数量、共享附件处理和短期 cleanup_token；用户确认后 execute 使用同一 token，事务中重新核对范围。期间若新增重处理任务，则跳过或报冲突，不按旧预览删掉新任务。

“一键清理已处理”可由界面内部完成预览和一次确认，不要求用户手工调用两个工具。MCP 发起清理时必须有明确用户意图，不能由素材处理器在成功后例行清理。

## 15.7 标准资源与通知

可提供 `babel-clipper://inbox`、`babel-clipper://records/{id}` 等自定义资源 URI，具体需带浏览器 profile 路由。MCP 资源更新仅发送有界提示，例如记录集合有新版本；正文和附件按需读取。

通知不持久代表业务任务，也不是“接收即执行”。客户端不支持或断线时，重连后通过数据库查询恢复；不实现专属 Codex/OpenClaw 的线程控制。必要时可在受支持的现有请求交互中使用 elicitation，但不能把它当成后台任意推送保证。[R28][R30]

# 16. 任务导出、附件交接与结果包

## 16.1 三种交接方式

标准 MCP 为主要机器接口。复制任务说明用于用户手工交接，内容必须包含来源、范围、预留策略、已保存附件和是否已处理；它不是一段模糊的“帮我看看这个视频”。JSON 导出用于备份、批量执行与迁移，保留同样的业务数据。

剪贴板只能携带文本时，复制说明不能声称附件已经传输。导出模式必须明确为“仅记录”或“记录加已有附件”。后者用文件包关联 manifest 和附件；大文件尚在外部目录时显示外部引用及可移植性限制。

## 16.2 建议任务说明

```text
请处理我明确选中的采集任务：cap_demo_001。
来源：原页面标题和可回访地址。
真实区间：10:00—12:00。
获取预留：前 10 秒、后 10 秒。
最终输出：本次仅保留真实区间，并导出指定帧。
策略：先取源片段；必要时可临时取较大范围后裁切。
已有现场附件：通过附件接口读取，不把引用当作文件本体。
请先登记领取，完成后回写实际范围、产物与失败信息。
不做 ASR、OCR、总结，不覆盖历史，不自动清理记录。
```

这个说明是执行契约的可读展示，具体命令由受信工具参数构造，不执行网页中夹带的脚本或任意 shell 片段。

## 16.3 结果目录

建议采用以下结构作为执行器约定，而不是浏览器必须自带的文件管理器：

```text
BabelContentClipper/
  <capture-id>/
    <job-id>/
      manifest.json
      source-info.json
      selected-text.txt
      clip.mp4
      audio.m4a
      frames/
        frame_source-0643.000.png
      verification.json
```

只创建用户要求或确实存在的产物，不生成空文件凑齐目录。不同工作项使用不同目录，重新处理不覆盖上一份文件。文件名对不合法字符做安全转换，记录原始标题但不把它直接作为未经校验的路径。

## 16.4 结果包要求

结果 manifest 至少说明源内容身份、原选区、预留快照、本次处理参数、实际获取与输出范围、捕获方式、音视频轨、截图时间、技术处理及验证等级。源资源获取失败但现场录制可用时，保留失败诊断与 fallback 结果。

临时下载的完整源文件属于执行器 scratch 数据，按本次授权策略和预算处理；它不同于用户已经存入采集记录的现场附件或正式成品。清理 scratch 不等于自动清理历史，更不能删除唯一可用素材后仍宣称有完整原始备份。

# 17. Agent 执行流程与源内容获取策略

## 17.1 执行端而非扩展承担重处理

Agent 接到明确指令后，读取任务、检查现有素材、登记领取、检查工具和权限、取源、处理、验证并回写。不需要每次重新发明下载命令；建议提供轻量执行 Skill 和固定参数脚本，复用 yt-dlp、FFmpeg 等成熟工具。[R37][R40]

缺少依赖可由执行端在用户授权范围内补齐，优先隔离工具目录和可信来源，不默认管理员权限、不要求插件做通用软件安装器。登录、浏览器授权和受保护目录仍由执行环境按规则处理。

## 17.2 获取优先级

第一优先：直接取得对应范围的源文件、媒体分片或源图片。yt-dlp 有时间范围下载能力，N_m3u8DL-RE 有流媒体范围选择能力，可以作为执行器候选，但实际可取得范围和裁切精度仍受源格式影响。[R37][R39]

第二优先：临时获取更大范围或完整源内容后裁切。用户最终要求的是片段，不意味着每个网络请求只能覆盖精确片段；允许合理额外读取索引、分片和相邻关键帧。需要限制临时下载大小、时长和磁盘预算。

第三优先：使用当时已经保存的现场录制或截图。如果没有现场备份、内容也无法回访，明确失败或部分成功；不能在用户关掉页面之后才承诺补录过去。

文本已在采集时完整保存时，直接使用该文本；不为了“统一流程”再次下载整篇文章。已有图片也优先验证与使用，只有失效或用户明确请求更高质量时再获取源资源。

## 17.3 媒体地址与身份

不能把 blob URL 视为永久可下载地址，相关对象随页面生命周期失效，且某些链接只是页面内对象引用。[R25] 保存可回访页面、内容标识、媒体时间和必要定位，执行时重新解析资源。

部分下载需要相同 IP、Cookie 或请求头，浏览器可看不等于另一个运行环境立即可下载。[R38] 对授权要求应报告清楚；不得把 Cookie 和令牌塞进普通复制文本、日志或对外素材包。必要会话访问通过受控本地能力获取，原始密钥不交给任意 MCP 客户端。

## 17.4 剪切、封装与精度

取得源媒体后优先直接裁切或封装，不把它播放一遍再录成第二份。FFmpeg 的流复制可以避免解码重编码，但任意切点、关键帧边界与精准输出不总能同时满足；需要在结果中说明实际范围和所用方法。[R40]

用户不要求首版逐帧极精确，因此以合理的起止容差、内容完整性和正常播放为目标。必要时对选区高质量重编码，或在后续研究 smart cut；不能宣称任何格式都可以任意点无损裁切。LosslessCut 和 smartcut 是策略与算法参考，不要求用户安装其完整编辑界面。[R42][R43]

## 17.5 输出组合

默认建议为视频原始片段保留音画，音频片段保留声音，文字保留原文，图片保留实际可取得资源。按用户参数额外导出音轨、指定帧或间隔图片。不要因为模型阅读方便，就只留下图片而丢掉动态画面和声音。

页面现场可能包含视频之外的图表、字幕或弹窗，现场录制在存在独特信息时不因源视频成功取得而自动丢弃。后续 ASR、OCR 和内容理解交给其他模块。

## 17.6 成功校验

“命令退出为零”不是全部验收。至少检查产物存在、可识别格式、时长/覆盖范围、应有音画轨、对应帧和来源映射。桥只验证到文件存在时，不把它扩大成已验证音画同步。

成功、部分成功、失败分别记录。网络不可用、媒体身份改变、权限不足、缺少工具、无法匹配时间轴等应有稳定错误码和用户可理解说明，不默认静默重试到无限次数。

# 18. 现场录制与失败兜底

## 18.1 录制不是全局默认后台行为

普通点播默认标记范围，保持轻量。对直播、动态页面或用户担心稍后无法取得的内容，提供明确的“标记并保存现场”开关。用户开启后才录制，不自动监听整个桌面、麦克风或所有标签页。

Chrome 提供 tabCapture 与 offscreen document 组合获取标签页音视频的路径；可参考官方示例和 Screenity 的录制生命周期设计，不必默认依赖另一个已安装的录屏扩展。[R08][R09][R44]

## 18.2 与起止、预留的关系

用户开始后才启动录制，不能补出开始前 10 秒。MediaRecorder 从启动起记录媒体流，前置余量只有取源、此前已有授权录制缓冲或其他真实素材才能取得。[R27]

第二次点击仍记录真实结束点。若用户开启后置现场预留，则界面显示继续保存尾部，并按可观察的媒体进度与合理安全上限停止；媒体暂停、关闭或切换时不无限等待，也不把不足的尾部伪报完整。

对未知媒体时间的页面录屏，预留需要以实际录制经过时间为参数，不能假装与源媒体秒数相同。来源媒体二倍速时，源时间与录制时间的对应关系要记录，预留是否取得以实际覆盖为准。

## 18.3 音频和画面完整性

录制必须验证有无音频轨及其来源，不能只拿视频轨就说保存了视频内容。默认不采集麦克风。权限拒绝、黑屏、静音、页面播放中断或被保护内容无法捕获时明确说明。

倍速现场录制保留未经校正版本；速度校正只能作为新派生产物，不覆盖原录制。截图不替代声音，已有字幕不替代实际音频；字幕只在可用且用户需要时作为原始文字附件。

## 18.4 分段保存与恢复

录制采用受控的分块写入或文件流机制，设置体积和时长预算。不能把长录屏全部放在内存里，最后一次性下载。MediaRecorder 的分块回调不自动等价于可独立播放的每个文件，保存方案需要验证封装与恢复能力。[R27]

关页或录制上下文退出时保存已有块、标记 interrupted，尽可能保留可恢复部分。录制文件体积大，不与元数据“JSON 很小”的假设混淆；根据能力写到授权本地目录或受控附件区，IndexedDB 保存 manifest 和必要引用。

## 18.5 交付优先级与执行时机

用户启用现场备份时，记录阶段先保住现场；后续执行仍按源内容优先。不能把“录制是兜底”理解成“下载失败之后再开始录制”。没有备份且无法重新取得时，以失败或缺失结束，不编造素材。

# 19. 配置项与默认行为

参数化不等于把所有技术参数暴露在首页。常用配置放在设置页，高级处理参数随执行任务查看和覆盖。下表默认值均为【建议实现】，已确认的能力和边界不可因默认值调整而改变。

| 配置 | 建议默认 | 生效规则 |
|---|---|---|
| 前置预留 | 10 秒 | 新采集快照；允许 0 和自定义 |
| 后置预留 | 10 秒 | 新采集快照；不覆盖旧历史 |
| 最终保留范围 | 执行预设可选 original/padded/custom | 未明示时使用可见的默认预设，结果报告实际值 |
| 取源策略 | 源片段优先 | 可授权临时大范围/完整下载 |
| 视频产物 | 音画片段为主 | 图片/单独音轨为可选附加输出 |
| 自动间隔截帧 | 默认关闭 | 用户或执行预设开启，不做 AI 选帧 |
| 无新增提醒 | 10 分钟 | 可改 5 分钟、自定义或关闭 |
| 提醒方式 | 插件提示；MCP 通知按能力增强 | 不绑定聊天会话、不等价于执行 |
| 现场录制 | 默认关闭，用户明确开启 | 显示录制状态，默认不采麦克风 |
| 录制前置缓冲 | 不启用持续后台缓冲 | 不承诺点击前现场可追回 |
| 历史保留 | 完成后持续保留 | 仅用户主动清理，不自动删除 |
| 快捷键 | 少量建议组合 | 允许浏览器重绑定与冲突检测 |
| 素材目录 | 用户授权后确定 | 不静默写任意系统目录 |
| 页面选择快照 | 当前授权页面的短期内存缓存 | 不形成浏览历史、不长期保存未采集选择 |
| 远程 Agent | 不作为首版默认路径 | 本地路径不自动跨机器有效 |
| 输出和临时预算 | 提供可见阈值 | 超限询问或安全停止，不无限下载 |

默认输出 original 还是 padded 可以在首次处理时让用户选择并保存为执行预设，但不能反复强迫回答。记录必须保留足够数据，使两种输出都不需要改写原历史。

# 20. 权限、安全与内容边界

## 20.1 最小权限

按功能申请 activeTab、scripting、contextMenus、storage、alarms 等需要的能力；录制、nativeMessaging、剪贴板和持续站点访问按实际实现与用户操作启用。不同浏览器权限语义需要验证，不在清单中盲目申请所有权限。[R01][R02][R04][R07][R09][R17]

站点选区快照需要提前运行时，说明为何需要该站点权限。拒绝扩展权限后普通阅读必须不受影响。浏览器内部页面、商店、其他扩展页和受限 frame 不承诺同等读取能力。

## 20.2 本地连接安全

本地不等于天然可信。Native Host 只允许本扩展 ID；本地 IPC/回环服务限定用户会话、鉴权和来源，区分浏览器 profile。不能向局域网公开无认证的 MCP/文件读取端口，也不能让任意网页请求触发下载、清理或读取本地任意路径。[R07]

若复用前两个 Babel 产品的桥，仍按功能隔离权限。Clipper 查询接口不自动获得其他插件的全部浏览器会话、Cookie 和文件权限。

## 20.3 页面内容是数据，不是命令

原网页选文、标题、字幕和附件不可信。它们即使包含“忽略之前指令”“安装这个脚本”等文字，也只能作为素材，不改变执行规则。下载和裁切命令由结构化参数及白名单执行器构造，避免 shell 拼接与参数注入。

HTML 预览清理危险内容。图片和媒体处理器按可信版本安装；导入包校验路径穿越、文件大小与格式，不允许附件文件名写出用户授权目录。

## 20.4 隐私与凭据

默认无云端账户、无内容上传、无后台全量浏览历史采集。用户主动导出或选择外部 Agent 时，界面说明数据离开扩展后的边界。内容处理是否在用户本地由实际 Agent 部署决定，不能因为扩展本地保存就宣称整个外部工作流绝不上传。

Cookie、Bearer Token、签名媒体地址等敏感信息不进入常规日志、复制文本或开放导出。必要资源重新解析；需要本地会话时通过授权工具访问，凭据不作为普通知识资源暴露给模型。

## 20.5 内容与许可

用于用户合法可访问、可保存的内容，不提供绕过 DRM、付费授权和访问控制的实现。工具支持某种网站不代表本产品自动拥有其素材的再分发权。录制也不是自动绕开限制的授权依据。

开源代码引入前核对 LICENSE、第三方依赖和发布产物。MIT/BSD、MPL、GPL/AGPL 以及 FFmpeg 不同构建的许可处理不能混为一谈；本文只记录可见许可与复用边界，不替代具体发布方案的许可审查。[R31][R32][R33][R34][R41][R44]

# 21. 可靠性、性能与可观察性

## 21.1 持久化可靠性

关键状态落库成功后再反馈；重启后恢复 open/interrupted、待办和未确认结果。临时后台停止不应丢失已经成功保存的文字和区间。持久化错误、存储配额不足或迁移失败显示明确提示，不继续假装采集正常。

主库只在扩展内，浏览器关闭后的即时查询不是首版硬保证。Agent 已经取到任务和文件可以继续按其环境执行；回写需要重连且有 ACK。只保存最小延迟回写收据，不引入自动覆盖 IndexedDB 的本地副本。

## 21.2 建议性能目标

以下是开发验收目标，需要在代表性设备上测量，不是已测性能声明。普通文本选区在脚本已可用且无需网络时，保存与反馈的 P95 目标可设为 500 毫秒以内；冷启动或权限提示单独测量。包含一万条纯元数据记录的测试库，列表分页首次展示目标为 1 秒量级，不同步载入全部正文或 Blob。

截图、录屏、网络取图与媒体处理使用进度和取消，不以相同的毫秒目标约束。没有录制或活跃采集时，不维持高频逐帧回调；没有待办时不唤醒 Agent、不做模型轮询。

## 21.3 数据规模与资源预算

元数据、全文文本、小图、长录屏和外部成品分别统计。长录制采用分块和预算保护，不能根据“主要是 JSON”推导所有附件都很小。空间不足先保住已有数据并安全停止新写入，不静默删除历史腾空间。

列表支持分页、按来源/状态/日期过滤和关键字查找。全文语义检索和向量数据库不属于首版；基本文字检索可作为轻量功能。

## 21.4 诊断信息

每次操作有 request_id/capture_id/job_id；日志只记录必要阶段、错误码、耗时和脱敏来源，不默认输出完整文章或凭据。用户可以导出诊断包，但诊断包与完整内容导出分开。

建议错误码包括：SELECTION_EMPTY、SOURCE_AMBIGUOUS、PERMISSION_DENIED、MEDIA_TIMELINE_UNKNOWN、CAPTURE_INTERRUPTED、STORAGE_FAILED、BROWSER_UNAVAILABLE、ALREADY_CLAIMED、RESULT_CONFLICT、ASSET_UNAVAILABLE、PARTIAL_COVERAGE、CLEANUP_CONFLICT。错误描述给出当前事实，不只显示技术栈异常。

# 22. 兼容性矩阵与技术验证计划

## 22.1 能力分级

对外支持清单应按能力标识，而不是只列平台名。一个网站可能支持文字选区和截图，却不支持可靠媒体取源；一个阅读器可能能复制文字，但不能恢复精确 CFI。

| 场景 | 通用路径 | 需验证或降级 |
|---|---|---|
| 普通 HTML 文章 | Selection/Range、右键文字 | 动态替换正文、图文多范围 |
| 标准 HTML5 音视频 | 起止位置、速度和来源 | 多播放器、广告、时间轴变化 |
| 公开视频站点 | 通用定位加少量适配器 | 稍后取源、分片和身份验证 |
| iframe 内容 | 对获授权 frame 读取 | 跨来源权限、嵌套与失效文档 |
| EPUB.js 阅读器 | 标准选区或选区接口 | CFI、清空选择、分页/滚动 |
| PDF.js 网页阅读器 | 文本层与页位置 | 页面旋转、缩放、选区映射 |
| 浏览器内置 PDF | 原生选择/复制等可行入口 | 不能预设可注入，失败走截图/导入 |
| Canvas/图片式阅读器 | 复制接口或框选截图 | 无文字即标注未获取，不做 OCR |
| 直播/动态页面 | 明确授权现场录制 | 时间窗口、音轨、页面关闭 |
| 本地文件页 | 用户允许的页面访问/手动导入 | 文件访问权限，非首期普遍保证 |
| 远程 Agent | 任务 JSON 与可访问附件 | 本机文件不可直接读取时明确失败 |

## 22.2 四组技术原型

**原型 A：选择读取。** 验证快捷键与右键取得相同选文；快照不会跨章节错用；读取不改变原菜单、滚动或翻页；PDF/EPUB iframe 能明确识别能力和失败原因。

**原型 B：源时间与延后处理。** 在 1 倍、1.5 倍、2 倍播放、暂停、前跳、回看和换内容情况下保存准确事实。关掉标签页后，以公开可回访源取得正确区间，记录预留和裁切误差。

**原型 C：统一 MCP 与数据库。** 两个客户端读取同一 profile 的待办，竞争领取只成功一次；Agent 回写出错可重试且不覆盖；浏览器关闭返回明确错误；不同会话不影响任务状态。通知能力缺失不影响主动查询。

**原型 D：现场附件。** 测试包含声音的录制、分块保存、尾部预留、权限拒绝、中断恢复和附件交接。确保只有位置记录时不显示已经拥有文件，录制成功也不显示为源媒体下载。

## 22.3 验证记录格式

每项兼容测试留下浏览器与版本、操作系统、样本来源、授权条件、成功能力、失败能力、截图/日志及复现步骤。不以 README 声明或单次人工成功代替回归样本。网站变化后只更新适配器与测试数据，不在核心中累积无边界的站点判断。

HTML 安全显示可以评估 DOMPurify；IndexedDB Promise 封装可以评估 idb。[R58][R59] 这类库用于减少基础错误，不改变“主存储在扩展、内容数据不执行”的规则。框架和打包器在原型后再选，不在 PRD 中因个人习惯强制某套大前端系统。

## 23.7 采用策略

建议自己实现 Capture/Job/Result 业务核心、IndexedDB Repository、MCP 契约与 UI；网页和阅读器采用接口适配；视频后处理委托外部成熟工具；录制保留薄模块。

# 24. 开发阶段、模块边界与交付清单

## 24.1 建议目录

```text
babel-content-clipper/
  apps/extension/
    background/       # IndexedDB 写入与浏览器事件
    content/          # 通用选区与媒体位置
    readers/          # 少量阅读器适配
    recorder/         # 明确授权的现场保存
    ui/               # 列表、详情、设置、清理
  packages/contracts/ # 类型、JSON Schema、错误码
  packages/storage/   # Repository 与事务规则
  packages/mcp/       # 标准工具/资源
  packages/bridge/    # 本地连接与 profile 路由
  integrations/runner/# 可选执行 Skill 和工具封装
  tests/fixtures/     # HTML、媒体、EPUB/PDF 等样本
  docs/               # PRD、权限、协议、兼容性说明
```

这是逻辑结构建议，不强制必须是多包仓库。小型实现可以合并文件夹，但契约、站点适配、存储和执行器不要纠缠成一个脚本。

## 24.2 阶段一：记录与存储闭环

交付选区采集、单键起止、padding 快照、标题分组列表、扩展 IndexedDB、真实状态与数据导出。此阶段确认历史不可覆盖、同内容可再次采集、基础清理不删除外部文件。

验证文字保存、媒体范围、页面关闭后记录仍在和选择不干扰原网页。还不能对外声称 MCP 自动处理、音画兜底或任意阅读器已完成。

## 24.3 阶段二：标准 MCP 交接闭环

交付轻量本地桥、查询、详情、附件读取、领取、结果回写、重处理和清理接口。两个不同 Agent/客户端通过同一套接口验证，不做会话适配。

配套最小执行 Skill，先处理公开可回访的标准音视频与已存文本，跑通原选区、扩展获取、成品范围、结果归档。断线、重复领取、重复提交和浏览器关闭必须有测试。

## 24.4 阶段三：阅读器与现场兜底

交付原阅读器兼容、iframe 选择测试、可用 EPUB/PDF 定位路径、复制/截图降级，以及明确授权下的标签页音画录制与附件交接。录制前后余量的真实边界必须可见。

通用层达到可用，再为少量代表平台补适配器。只发布实测通过的能力，其他场景清楚标注限制。

## 24.5 阶段四：提醒、体验与发布加固

交付闲置一次性提醒、可选事件提醒、通知能力协商、快捷键冲突提示、清理预览、导入迁移、存储诊断和权限说明。完成性能、异常恢复与许可证清单检查。

这些阶段是实施顺序，不是把已确认的核心要求永久推到以后。正式首期版本宣称哪些能力，就必须完成相应验收；不存在以一个纯书签原型冒充完整片段采集器的发布。

## 24.6 交付物

交付浏览器扩展构建包与源码、最小 MCP/桥安装与配置说明、记录和结果 Schema、执行 Skill/工具契约、测试夹具、支持能力矩阵、权限与隐私说明、第三方许可清单、诊断与备份恢复说明。

不要交付强制依赖的云端后台，不要求安装所有参考项目。用户没有 Agent 时仍可使用基础采集和导出；有标准 MCP 客户端后再连接执行能力。

|---|---|---|
| D-01 | 无新增达到设定阈值 | 只提醒一次，不自动下载 |
| D-02 | 阈值前新增采集 | 重设一次性计时，不按旧时间误提醒 |
| D-03 | 未回应提醒 | 不视为同意，不每隔阈值催促 |
| D-04 | 客户端不支持通知 | 插件提示与主动 MCP 查询仍能使用 |
| D-05 | 未结束录制且长时间无点击 | 不因闲置替用户结束真实区间 |
| D-06 | 现场录制声音和画面 | 两类轨道按实际保存，缺失明确标注 |
| D-07 | 录制开启前没有缓冲 | 不承诺前置 10 秒现场已经取得 |
| D-08 | 录制中断 | 已保存部分可追踪，不显示完整源文件 |
| D-09 | 清理一个来源已处理项 | 未处理和活跃任务保留，不删除整个混合分组 |
| D-10 | 清理全部已处理 | 数量范围可见，外部成品文件不被删除 |
| D-11 | 清理预览后新增重处理 | 检测冲突，不能删掉新活跃任务 |
| D-12 | 明确通过 MCP 清理 | 与 UI 规则一致，不由普通处理流程自动调用 |

## 25.5 发布门槛

核心阻断问题包括历史覆盖、错源采集、凭据泄露、未授权自动执行、清理误删成品、重复领取、回写假成功、跨章节快照误用、页面录制无提示和采集失败伪报成功。存在任一未解决阻断问题时，不发布为稳定版。

本轮没有实际测试结果，因此验收表目前均属于待执行计划，不附虚构通过率。支持矩阵必须与测试日志一致。

# 26. 风险、待验证事项与后续扩展

## 26.1 当前无需再向产品负责人索取的决定

名称、浏览器产品形态、轻量记录与外部执行分工、单键起止、padding 双范围、扩展 IndexedDB、历史不覆盖、手动清理、MCP 主动查询、非强制通知、快捷键/右键、电子书不干扰原则均已确定。实现阶段不应反复询问这些已回答问题。

## 26.2 工程阶段需要验证而非重新定义的事项

一是浏览器与本地 MCP 的可靠连接与回写 ACK，特别是多 profile、多客户端和浏览器退出。二是自定义阅读器选择在实际事件时序下能否取得。三是指定公开视频源能否在页面关闭后恢复选中范围。四是现场录制的音轨、分块恢复、时间映射与体积。五是客户端标准资源通知的实际展示方式。

这些问题用原型和兼容矩阵解决；无法通用时提供明确降级，不通过扩大产品范围或引入大型调度系统掩盖。

## 26.3 主要风险与处理

| 风险 | 应对 |
|---|---|
| 网页或播放器改版 | 通用层与适配器分离，保留夹具与能力回归 |
| 源链接或登录条件失效 | 保存可回访身份，执行时解析；必要现场由用户提前保存 |
| 浏览器退出导致回写不可达 | 明确 pending ACK，保留最小结果收据，重连幂等写回 |
| 选择被页面清空 | 快照、阅读器接口、原生复制和截图分级，不误用旧数据 |
| 长录制占用过高 | 预算、分块落盘和中断保护，不自动删历史腾空间 |
| 源文件精确切点不可直切 | 记录实际偏差，可按授权重编码，不虚称任意点无损 |
| 开源许可不适合直接合并 | 按模块研究，核对依赖和分发，避免整体 Fork 后再补救 |
| 认为 MCP 通知能启动任何 Agent | 稳定入口是查询；通知只是能力增强，不承诺会话控制 |
| 重试导致历史覆盖或重复输出 | 独立 job、幂等键、原子领取和终态冲突检查 |

## 26.4 可以扩展，但不应挤进当前核心

可后续增加更多阅读器适配、Firefox/Safari 支持、远程安全附件交接、显式导入原网站批注、已有素材的批量导入、用户控制的输出预设和 DSH 原生接口。

ASR、OCR、总结、语义关键帧和学习系统保持外部模块属性，即使以后生态中出现，也不把它们重新定义为 Clipper 的基础职责。跨 Agent 会话绑定和自动聊天注入不因工程方便重新加入。

# 27. 决策演变与明确排除项

本章保留讨论如何收敛，避免开发者从早期描述中恢复已经被更正的方案。

| 早期讨论方向 | 最终规则 |
|---|---|
| 主要围绕视频笔记工具 | 改为通用原始片段采集，文字、图片、音频、视频、阅读器均可进入 |
| 只保存周期截图 | 连续音画片段是默认建议底本；图片辅助或按用户参数输出 |
| 所有功能放进扩展 | 扩展记录/现场保存，Agent 与工具执行下载、裁切、截帧 |
| 必须马上获取全部文件 | 可延后处理；当场容易丢的信息即时保存 |
| 先下载失败，再想办法录屏 | 录屏必须在现场启用；不存在事后凭空补录 |
| 自动判断刚才多长内容重要 | 不预测长度；用户单键开始/结束，另设前后余量 |
| 只保存扩展后的时间 | 必须同时保存真实点、余量、获取范围和最终输出范围 |
| 标记后 Agent 自动开始下载 | 提醒不执行；用户明确请求或确认后才处理 |
| 强制续接同一个 Agent 会话 | 不管理会话、不做逐客户端线程适配 |
| MCP 一连接就保证能反向唤醒模型 | 主动查询是通用基础；标准通知按能力增强 |
| 只靠 Agent 记住已处理项 | 处理状态与历史在扩展主库，Agent 经 MCP 回写 |
| 用本地 JSON 和浏览器库双主存储 | 扩展 IndexedDB 为主；JSON 用于导出、备份及最小待回写收据 |
| 完成后自动清理或替换旧记录 | 完成保留历史；明确清理才删除；重新执行新增结果 |
| 按 URL/区间自动禁止重复采集 | 用户可有意重复；系统只防通信/派发误重复 |
| 列表展示完整文章和全部参数 | 标题、真实时间、短选文与小图；详情才展开完整信息 |
| Babel 再做一套阅读器划词菜单 | 沿用原选择与菜单，快捷键/右键接收，不接管阅读体验 |
| 所有电子书都可直接 DOM 取文字 | 按渲染和接口分层，失败可复制或截图，不做 OCR 或权限绕过 |
| 把所有参考项目当成依赖 | 按交互、协议、代码、执行工具四类筛选，不整体搬入 |

本 PRD 的完整性体现在最终规则、场景、约束、实现边界和参考材料都可追溯，不是把早期互相矛盾的方案同时当作产品承诺。
