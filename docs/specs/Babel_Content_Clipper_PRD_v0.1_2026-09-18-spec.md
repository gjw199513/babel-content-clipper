## 需求 (Requirements)

### 功能需求

| 编号 | 需求规则 | 来源 |

| R-29 | ASR 模型与执行依赖不随扩展或 MCP 发布包内置。MCP 发布机器可读与人类可读的处理指南，明确模型、文件、摘要、依赖建议、失败边界和本地目录；实际检查、安装、下载与缓存由 Agent 执行。 | 第 13 轮用户明确“给 Agent 指导，不由 MCP 执行” |

| R-31 | 指南要求 Agent 固定仓库、提交版本、必需文件清单、期望大小/摘要并在落盘后校验；临时文件不得冒充可用模型，重复执行可复用 Agent 自己已校验的缓存。 | 第 12 轮完整性要求；第 13 轮 Agent 执行 |
| R-32 | MCP 提供明确的 Agent 处理指南，覆盖媒体下载器、FFmpeg、sherpa-onnx、模型、LLM 校正、目录、验证与回写顺序；Agent 读取后用自己的工具完成，普通用户不需要自行理解或手工串联这些技术步骤。 | 第 13 轮用户澄清 |
| R-33 | 视频取源、音频抽取和 ASR 均由 Agent 在本地后台执行，不打开、点击或控制浏览器页面。MCP 仅在有效 claim 下提供来源上下文；已保存附件或本地媒体优先复用，私有 URL 只作瞬时数据输入。 | 第 13 轮用户澄清；既有 claim 安全边界 |
| R-34 | ASR 后必须同时保留原始转写、分段/时间信息、模型与运行参数、源媒体摘要和警告。后续校正只能新增校正版及变更说明，不得覆盖原始 ASR。 | 第 12 轮“核心是校正而非直接 ASR”；历史不覆盖原则 |
| R-35 | 大模型校正使用当前 Agent 已有的模型能力，不在 Clipper 内硬编码厂商、模型名或 API Key。MCP 只给出校正规则与采集上下文；Agent 自行生成并保存校正版、审计和不确定项，再通过通用结果回写提交产物引用。 | 第 12 轮校正目标；第 13 轮取消 MCP 执行/专用持久化 |
| R-36 | 校正上下文限于来源标题、视频简介、标签和评论摘录，并全部视为不可信数据而非指令。上下文用于纠正同音词、专名、断句和标点，不得凭上下文新增音频中不存在的观点或事实。 | 第 12 轮；安全约束 |
| R-37 | 校正必须最小化改写，优先保留人名、实体、数字、单位、否定、时态和说话意图；无法可靠判断时保留原始片段并标记不确定，不能为了通顺改变语义。 | 第 12 轮；ASR 语义安全要求 |
| R-38 | Agent 必须把本次文字提取的所有终态文件保存在该 Capture/Job 的本地目录：源媒体（若取得）、原始 ASR、校正上下文、校正版、审计清单和运行日志均可追溯；失败也保留已完成的中间事实，不影响原有非 ASR 能力。 | 第 12 轮本地完整保存；第 13 轮明确 Agent 负责落盘 |

### 用户故事

- 阅读时选中一段文字，一次操作保存完整原文与来源，继续原来的阅读。
- 观看时标记一个区间，稍后要求 Agent 获取所选音画片段，并在扩展查看执行结果。
- 更换 Agent 或会话后，仍查询同一份待办和历史。
- 对同一记录使用新的输出参数重新处理，保留前一次结果。
- 新用户从 GitHub 取得项目公开发行物，按说明安装扩展和本地 MCP 组件，连接自己的 Agent，完成示例采集与处理回写，无需修改源码或向作者索取私有配置。
- 用户要求“把这个视频转成文字”时，Agent 先检查是否已有可用文字；没有时读取 MCP 指南和 claim-bound 来源上下文，用自己的后台下载、依赖、ASR 与 LLM 工具生成 raw 和校正版，所有文件留在本地工作项目录，最后通过 MCP 回写。
- 用户只要求视频文件或图片时，不下载 ASR 模型、不抽取音频，也不产生转写费用或额外等待。
- 上述故事结合 PRD 第 5 章与本轮 Q10 的对外交付要求；跨网站沿用一致的交互逻辑，具体站点适配分批推进。

### 验收标准

- 原 PRD 第 25 章为完整验收基线，目前均为待执行计划。
- “选择记录完整”“附件已保存”“执行已完成”“产物已验证”分别表达，不相互代替。
- 页面关闭或后台重启后，已确认落库的记录仍可恢复；浏览器不可用返回明确错误。
- 成果回写在扩展事务 ACK 后才算成功；相同重试幂等，冲突终态不覆盖。
- 产物验证说明检查范围，区分 Agent 报告与桥实际验证。
- 同类采集操作在不同已支持网站上遵循一致的交互逻辑；具体兼容样本由工程验证逐批补充。
- 同次采集：10:00 开始，看到 11:00 后回到 10:30，再看到 12:00 结束，成片中的 10:30—11:00 只出现一次；前后预留仍按配置添加。
- 再次主动采集同一来源的相同区间，正常生成独立 Capture；明确重新处理时产生新 Job/Result，不合并或删除已有记录与结果。
- 上述内容重复规则不改变通信幂等：同一次请求重发不新增记录，同一个工作项不被两个执行者重复领取。
- 用户主动打开记录列表时默认使用侧栏；点击“展开管理”在独立标签页查看完整管理界面，两者展示同一 profile 的同一份记录。
- 在同一浏览器窗口内切换标签页、打开新网站、同标签页跳转后，按支持浏览器的全局侧栏能力保持可用；受浏览器行为影响关闭后，重新打开可恢复查看状态，已保存数据不丢失。
- 侧栏和独立页之间切换时保留筛选与当前查看的记录；目标已被用户清理时刷新列表并说明，不展示过期详情。
- 两个视图同时打开时，采集、领取、结果回写和清理应更新各自显示；关闭其中一个视图不取消另一个视图或后台的采集状态。
- 将一条未处理记录设为仅收藏后，内容仍可查看，待处理查询和提醒不再包含它；重新加入待办后可再次被明确请求处理。
- 两个 Agent 同时领取同一工作项，只有一个能够将其变为处理中并取得执行权；另一个跳过，不重复执行。
- 处理成功并完成回写后显示已处理；默认一次自动重试仍失败且执行已结束时显示处理失败，保留错误信息，不回到未处理，也不一直显示处理中。
- 一次自动重试期间仍由原 Agent 占用；普通待处理查询和领取不自动纳入处理失败项，不因新一轮查询再次执行同一错误任务。
- 失败详情至少包含实际错误信息、失败阶段和重试次数；原因尚未确定时如实说明，保留可供排查的脱敏上下文。
- 历次成功或失败结果继续独立保留；当前状态调整不删除历史，也不把曾经失败描述为从未尝试过。
- 仅配置全局默认目录，或仅配置 MCP 连接目录时，均可解析出有效输出位置；两者不互为必填前置。
- 多个目录配置同时存在时，按本次任务指定、MCP 连接配置、全局默认的顺序采用第一个已提供值；单次覆盖不修改已保存默认值。
- 本次使用的目录及其配置来源可查看，执行参数和结果记录实际位置；修改默认值不移动既有成品，也不改变进行中任务已经确定的输出位置。
- 同一视频采集 3 条独立记录后一起处理，每条记录仍有自己的状态和结果；只要求视频片段时分别对应各自的视频，不自动拼接或去重。
- 一条记录可按后续指令产生视频和音频等多个产物，各产物关联同一条原记录；不因产物类型不同而伪造新的采集事实。
- 批次内某条失败不撤销其他条已完成的结果；重试、重新处理和清理继续按各条记录的状态执行。
- 为一条片段启用现场保存后，该片段按本次配置保存音画及可取得的尾部预留；下次手动标记恢复为普通区间记录，不沿用录制模式。
- 在声明支持的干净环境中，仅使用公开产物和文档，完成安装扩展、本地 MCP 配置、连接检查、示例采集、Agent 读取与处理、结果回写的流程。
- 首版交付包含可安装的扩展构建产物、可启动的 MCP/本地桥组件及其源码、快速开始、依赖与版本要求、配置示例、支持能力矩阵和常见故障排查。
- 安装流程说明每一步的预期结果；连接检查区分 MCP 未就绪、浏览器未运行或扩展未连接等问题，不能仅以本机开发环境中的成功代替对外交付验收。
- 公开发行物与对应源码版本可追溯；已有基础安装、许可、备份恢复和兼容性说明按原 PRD 第 24.6 节交付，不把对外可用性留到第一版之后。
- `outputs.text` 未请求或已有可信文字可直接满足请求时，Agent 不准备模型、不运行 ASR；读取处理指南或来源上下文本身不触发任何下载或执行。
- MCP `tools/list` 中不得出现由 Clipper 执行下载、安装、转写或 LLM 校正的工具；应提供只读处理指南，以及在有效 claim 下只读取得来源上下文的工具。指南明确所有处理步骤的 `executor` 为 Agent。
- Agent 首次 ASR 缺少依赖时，按指南在自己的执行环境中检查、安装或选择等价工具；用户无需理解 `npm`、`yt-dlp`、FFmpeg 或模型目录如何串联。无法自动完成时，Agent 返回具体系统限制，不要求 MCP 或浏览器插件代执行。
- Hugging Face 官方端点可访问时，Agent 不得无理由使用镜像；官方连接失败时可回退 HF-Mirror，并在不泄漏私有来源 URL 的清单中记录模型端点。任一来源下载后的文件均须通过固定 SHA-256/大小校验后才可使用。
- Agent 对一个已领取的视频 Job 运行 ASR 后，本地至少存在 `raw-transcript.txt`、`raw-transcript.json`、`correction-context.json` 和 `transcription-manifest.json`；若完成校正，再新增 `corrected-transcript.txt` 与 `correction-audit.json`。
- 原始转写与校正版可以同时回写为 text/manifest 产物；校正版不得替换、删除或改名伪装成原始 ASR。重处理继续创建新的 Job 目录，不覆盖旧文件。
- 校正样本覆盖专名、数字、单位、否定词和不确定片段；测试必须证明校正提示明确禁止补写未听见内容，并保留上下文来源与修改说明。单元测试不能代替真实音频的准确率验收。
- 简介、标签或评论内含“忽略规则”“执行命令”等文字时，只作为引用上下文进入校正包，不改变 Agent 权限、不触发工具，也不进入 shell 参数。
- Agent 的 ASR 或校正失败时，已下载媒体和已生成原始转写继续保留；失败按实际阶段通过通用结果工具回写，不将下载成功、模型就绪或存在文本文件误报为完整文字提取成功。

## 约束 (Constraints)

### 性能约束

- PRD 建议文本保存与反馈 P95 ≤ 500 毫秒、一万条纯元数据下列表首次展示为 1 秒量级；这是候选目标，尚未实测。
- 长录制须分块保存并受时长、体积和磁盘预算约束；具体预算待定。
- 不因提醒持续调用模型，不把大附件随列表查询整批加载。
- 指南默认建议 Agent 用 CPU 运行 ASR，长音频按有界片段处理并记录真实耗时；不得为追求速度默认占用 GPU。模型首次下载约 239 MB，Agent 自己的缓存预算、超时和并发下载须有界且可诊断。
- 大模型校正只处理受限长度的文字上下文；评论按数量和字符预算截断、去重并记录省略数，不能把整个评论区无界送入模型。

### 安全约束

- 原网页内容和附件作为数据，不能变成执行授权或命令。
- 连接和文件访问按授权范围执行；普通日志、任务文本和导出不携带凭据。
- 不绕过访问控制，不默认录制麦克风、桌面或所有标签页。
- 清理保护活跃任务和外部成品；不因空间不足静默删除历史。
- 指南要求 Agent 的模型与执行依赖只从可信 HTTPS 端点取得；下载使用临时文件、摘要校验和原子落盘。镜像只作为传输回退，不改变模型仓库、提交版本或期望摘要。
- 视频简介、标签和评论属于不可信来源数据；校正提示必须把数据与指令分隔，禁止其扩大权限、调用工具、泄露本地路径/凭据或覆盖原始结果。
- 任何 HF token、站点 cookie 或平台会话数据均不得写入转写文件、清单、日志或 MCP 返回正文。公开模型默认不要求 HF token。

### 兼容性约束

- 主库为扩展自身 IndexedDB，导出 JSON 和待回写收据不构成第二个业务主库。
- 通用能力优先，阅读器和平台按实测能力分级；截图不伪称已取得原文。
- 本轮确认：初期支持部分网站、逐步扩充；站点差异不改变统一的用户交互规则。
- 首版以本机 Agent 为建议路径；本地文件路径不自动具备远程可访问性。
- 采集、桥接和执行器可组合；不强制依赖 Downloader、DSH 或特定 Agent 会话。
- ASR 是 Agent 侧可选后处理，不进入扩展、Core 或 Clipper MCP 的执行职责；MCP 只提供指南和受控来源交接。OCR、摘要、语义选帧和学习反馈同样属于外部模块。新增指南不得改变不请求文字时的原流程。

### 架构决策

- 沿用原 PRD 的四层职责：扩展采集与存储、本地桥受控交接、用户 Agent 执行、后续系统理解与使用素材。
- D-01（本轮 Q1 确认）：通用网站是产品目标，交互逻辑一致；兼容范围分批增加。首批网站名单不是继续讨论通用交互的前置条件。
- D-02（本轮 Q2 确认）：默认成品保留前后预留；时长在插件设置中配置。配置变化沿用 PRD 规则，只影响新记录，不覆盖历史参数快照。
- D-03（本轮 Q3 确认）：只在同一次采集内消除回看导致的成片重复；不同采集与明确发起的新处理互不进行内容去重。用户不希望系统因识别出相同内容而阻止、合并或忽略主动操作。
- D-04（本轮 Q4 确认）：侧栏优先，用户可展开为完整管理页。“全屏打开”在本轮界面方案中落实为占满独立标签页的扩展管理页面，浏览器级全屏沿用浏览器自身操作。
- D-05（基于 Q4 的实现选择）：独立管理页属于扩展本地页面，与侧栏共用存储和业务服务，不增加云端网站、账号或第二份数据库。视图状态恢复属于体验要求，具体恢复机制在原型中确定。
- D-06（按本轮 Q6 修订）：处理状态为四个，增加处理失败。用户明确修改了 Q5 的“失败回未处理”规则，原因是避免反复触发相同错误。处理中仍承担并发占用语义；仅收藏通过待办参与设置表达，不再新增处理状态。
- D-07（本轮 Q6 确认）：允许在本次任务中做一次有限自动重试；仍失败则保留失败状态和错误信息，供用户或 Agent 排查，不能自动重新混入未处理任务。
- D-08（本轮 Q7 确认需求、助手确定细节）：输出目录支持固定默认和单次替换，采用本次任务指定 > MCP 连接配置 > 全局默认的优先级。插件配置是可选入口，不能要求已经在 MCP 配置目录的用户再填写一次。
- D-09（本轮 Q8 确认）：记录是独立交接与状态管理单元。跨记录合并完全交给外部后续处理，不作为 Clipper 的输出选项；视频、音频、文字等具体产物按后续任务要求处理并回写对应记录。
- D-10（本轮 Q9 确认）：现场保存开关仅对本次片段生效，下次恢复普通标记。本次已经约定的尾部保存继续按原规则完成，不因下次默认模式恢复而截断。
- D-11（Q10 确认交付对象，Q11 细化使用许可）：第一版面向其他个人使用者，项目计划在 GitHub 公开源码。安装、MCP 接入和上手验证作为第一版组成部分；个人非商业使用可用，商用另行取得作者授权。
- D-12（本轮 Q11 确认）：这些插件属于作者 DSH 的组合方案，默认不授予第三方商用权，不采用 MIT 方案。商业授权由作者保留，具体许可文本后续再讨论；本轮不以许可证选型继续追问。
- D-13（第 12 轮确认）：文字提取采用“已有可信文字优先，缺失时才 ASR”的按需路由。单纯下载视频、裁片或导出 Capture 不隐式触发 ASR。
- D-14（第 13 轮修订，替代第 12 轮执行型方案）：ASR 不是 MCP 或浏览器扩展的执行能力。MCP 只提供结构化指南、采集包和有效 claim 下的来源上下文；Agent 执行下载、依赖准备、ASR、校正和文件生成。扩展只保存采集事实与有界校正上下文。
- D-15（第 12 轮模型选择、第 13 轮责任修订）：指南建议 Agent 采用 sherpa-onnx 官方 Node-Addon，避免普通用户被要求理解 Python venv；SenseVoice INT8、CPU、16 kHz WAV 和分段思路继续作为默认参考，但包安装与运行由 Agent 负责。
- D-16（第 13 轮修订）：发布包不捆绑 239 MB 模型，也不声明 Hugging Face、sherpa-onnx、FFmpeg 或 yt-dlp 为 Clipper 运行依赖。Agent 按指南下载并验证，官方 Hugging Face 优先，HF-Mirror 仅作连接失败后的传输备选；缓存位置由 Agent 管理并与业务输出分离。
- D-17（第 12 轮实现选择）：当前 Agent 的 LLM 负责语义校正。这样不同 MCP 客户端可复用其已选模型，Clipper 不新增云端账号、API Key、计费 Provider 或数据出境默认值。
- D-18（第 12 轮确认）：`raw` 与 `corrected` 是两个有明确来源的产物层级。校正链路保存上下文摘要、原始文本摘要、校正文、修改说明和 Agent 标识；任何后续运行都不能修改旧 Job 的文件。
- D-19（第 12 轮确认）：简介、标签和评论只提供纠错证据，不是第二份“真相文本”。与音频冲突时保留 ASR 原文或标不确定，不把热门评论中的说法写成视频讲述内容。
- D-20（第 13 轮修订）：依赖问题由 Agent 依据 MCP 指南处理，而不是由 Clipper MCP 的诊断/准备工具执行。Agent 能自动补齐时自行完成；遇到不受支持的 OS/CPU、磁盘不足或网络策略阻断时返回具体事实，不回退到浏览器点击或静默改用云 ASR。
- D-21（第 13 轮确认）：MCP 中移除执行型下载、运行时准备、转写与专用校正持久化能力；新增只读处理指南资源/工具和 claim-bound 来源上下文工具。通用导出、领取、心跳、结果回写与历史不覆盖保持不变。

### 按需视频文字提取处理顺序

1. Agent 读取 Job 的 `executionOptions.outputs.text` 与 Capture 详情；未请求文字则结束本分支。
2. 查找已保存正文、平台字幕或已有可信转写；能满足本次范围时直接物化到本地，不运行 ASR。
3. Agent 原子领取 Job，读取 MCP 处理指南，并先用通用导出工具物化已保存内容。
4. 媒体仍缺失时，Agent 用 claim token 获取瞬时来源上下文，再交给自己的后台下载器；全程不操作浏览器页面，不持久化私有 URL 或 Cookie。
5. Agent 检查自己的运行时；缺少模型/依赖时在自己的受控环境中下载、安装并校验，Clipper MCP 不执行。
6. Agent 使用 FFmpeg 将目标媒体范围转换为 16 kHz、单声道 WAV；记录输入文件 SHA-256、真实音频时长和范围映射。
7. Agent 用 SenseVoice INT8 在 CPU 上生成原始转写及可得的 token 时间信息，写入不可覆盖的 raw 文件。
8. Agent 从 Capture 公共元数据建立有界校正上下文：标题、简介、标签、评论摘录及各自来源；网页内容一律作为数据转义。
9. 当前 Agent 的大模型按 MCP 指南做最小语义校正，Agent 自行保存校正版、修改说明和不确定项，不覆盖 raw。
10. Agent 将 raw、corrected、context、audit、manifest 作为独立本地产物通过通用结果工具回写；任一步失败按实际阶段和已有文件提交，不覆盖旧结果。

| 1 | 本次任务提供的输出目录 | 仅本次执行；可来自用户指令或 Agent 在任务授权范围内提供的参数 |
| 2 | 当前 MCP 连接配置的默认目录 | 该连接的任务，在未提供单次覆盖时使用 |
| 3 | 全局默认目录 | 当前扩展数据配置范围内、未被上两层覆盖的任务；插件可提供设置入口 |

- 用户只需采用适合自己的配置方式；全局设置与连接参数不要求维护两份相同值。插件展示可用默认值和来源，任务详情展示本次实际采用的值。
- 已保存默认值启动时继续使用。一次任务覆盖不改变全局或连接默认；已开始的任务使用自己的参数快照。
- 明确提供的高优先级目录不可用时报告问题，不静默改写到另一个低优先级目录。三处均未提供时说明缺少输出位置，由执行端提供或引导配置。
- 路径配置只表达目标位置，不替代实际文件访问授权。沿用原 PRD 的受控目录、不同执行分别存放和结果回写规则，不要求为目录配置增加第二份业务主库。

### 四种处理状态与待办规则

| 当前处理状态 | 含义 | 领取与后续行为 |
|---|---|---|
| 未处理 | 尚未执行当前处理请求，或用户明确新建了再次处理的工作项 | 参与待办、采集完整且无占用时，才可在明确执行请求下领取 |
| 处理中 | 已由一个 Agent 领取，正在执行或进行本次允许的有限重试 | 其他 Agent 不能领取；失联诊断也不直接释放占用 |
| 已处理 | 本次要求已完成，并已收到扩展持久化回写确认 | 保留历史；用户明确重新处理时创建新的执行记录 |
| 处理失败 | 本次执行已明确失败，且允许的重试已耗尽或错误不适合自动重试 | 保留错误信息，排除普通待处理领取；排查后明确发起新执行，不改写旧失败结果 |

- “仅收藏”改变是否参与待办，处理状态仍可为未处理；它不伪造成功结果，也不清空内容。重新加入待办不自动开始执行。
- 四态描述当前处理进度；失败原因、部分产物、取消原因、连接异常继续作为详情或历史事实保存。采集自身是否有完整起止点仍单独记录。
- 已经写入的失败结果不被后续成功覆盖；用户再次明确处理形成新的执行记录。已有成功历史后再发起重处理，也保留前一次成功结果。
- 对用户要求的必需产物缺失，保留已取得的部分并说明；本次处理与允许重试结束后仍不满足要求，进入处理失败，不能因某个子步骤成功就宣称全部完成。
- 只有确认执行已结束，才能按明确最终失败提交处理失败并释放占用。失联或超时不直接等于已知失败，先保留处理中并附异常说明、核实执行情况；确认最终失败后进入处理失败，不把它退回未处理。
- 普通查询、提醒或重新加入待办均不自动授予执行权。处理失败项需明确发起新的重试或重新处理，不能仅通过刷新列表或切换收藏设置自动重跑。
- 一次自动重试属于本次已授权执行内部，保留原占用，记录重试事件；提交终态结果后不再修改该结果。登录或权限缺失、外部执行是否停止尚不明确等情况不盲目自动重试。

### Q13：MCP 只指导，所有后处理由 Agent 执行

**用户修订**：整个逻辑应是 MCP 提供“文档解析包”或明确指导建议，而不是让浏览器插件中的 MCP 执行。MCP 除了对应内容的裁剪、交接与管理，其他下载、依赖、转文字和校正操作都让 Agent 执行。多数用户不知道怎么做，因此 MCP 要把指导写得足够明确，让用户调用的 Agent 能直接读取并照此处理。

**对 Q12 的影响**：Q12 对按需 ASR、sherpa-onnx/SenseVoice、Hugging Face 优先与 HF-Mirror 连接回退、校正证据、raw/corrected 分离和本地完整保存的目标继续有效；“MCP 自己准备依赖、下载媒体、运行 ASR、专用保存校正版”的执行型设计被本轮明确否定并替代。

**最新职责归纳**：

- 扩展负责用户主动裁剪和保存可得事实，包括正文、附件、媒体区间与有界简介/标签/评论上下文。
- Clipper MCP 负责读取/导出、原子领取、claim-bound 来源上下文、心跳、通用终态回写，以及发布机器可读和人类可读的 Agent 指南。
- Agent 负责判断是否需要文字，使用自己的下载器、FFmpeg、sherpa-onnx、模型缓存和 LLM，生成并验证本地文件后回写。
- MCP 工具不得以“帮助用户”为由暗中安装包、下载模型/媒体、运行本地进程或控制浏览器；帮助形式是把固定参数、顺序、边界、错误处理和产物契约写清楚。

**指南交付内容**：

- 硬边界和职责表；
- 是否进入 ASR 的决策条件；
- `get record → claim → read guide → export capture → get acquisition source → Agent processing → commit result` 的明确顺序；
- 固定模型 revision、文件大小、SHA-256、Hugging Face/HF-Mirror 回退条件；
- 推荐但不随 Clipper 分发的 Agent 依赖；
- 无浏览器点击、参数数组、防 shell 注入、私有 URL/Cookie 不落盘规则；
- 16 kHz 单声道、CPU、80 维特征、ITN、30 秒分块等 ASR 参考参数；
- 不可信上下文、最小校正、数字/单位/否定/专名/不确定项保护；
- 每个 Capture/Job 的本地文件树、失败保留和 `agent_reported` 回写要求。

**语义完备性评估，第 1 次**：COMPLETE（职责边界）。用户已明确谁执行、MCP 提供何种帮助、浏览器操作禁止边界，以及普通用户不需要掌握底层步骤的目标；不再需要在“执行型 MCP”与“指导型 MCP”之间选择。

**语义完备性评估，第 2 次**：COMPLETE（与既有规则复核）。最新方案保留按需触发、本地完整保存、历史不覆盖、原子领取和通用回写；移除的仅是 MCP 进程内后处理执行，不影响扩展采集和已有交接功能。跨平台依赖能否由某个 Agent 环境成功准备仍是工程兼容性事实，不是新的产品选择题。
