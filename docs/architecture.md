# 架构与边界

## 数据与执行

扩展采集用户明确选择的内容，并将 Capture、Job、Result、附件、设置存入扩展来源的 IndexedDB。网站内容脚本只能上报本次采集所需数据，不能使用管理或结果回写接口。

Capture 封存后保存不变的来源、原文、真实点击、观察事件和参数快照。处理进度属于 Job；最终结果属于 Result。重复提交同一请求是幂等行为，用户再次主动采集或重新处理则生成新的记录。状态只有未处理、处理中、已处理、处理失败；仅收藏单独控制是否进入待办。

侧栏和独立管理页通过同一扩展后台访问主库。它们切换或关闭不会建立新数据库，未得到事务确认的写入不会显示成功。

## 本地交接

扩展主动连接 Native Messaging Host。标准 MCP stdio 进程经过本机 broker 将受控请求路由给指定 profile 的扩展。桥只保留连接和请求状态，不缓存一份独立的业务主库。浏览器不可用时返回明确错误。

浏览器和 MCP 使用相同版本的请求与响应契约。每个请求有独立传输 ID；业务重试另有持久化 requestId。多个连接请求同一 Job 时，以 IndexedDB 事务中的原子领取为准。连接超时不等于外部执行已终止，也不会自动释放占用。

附件按有界分块交接。桥输出文件只能使用已经解析、验证的目标目录；默认目录优先级为任务指定、MCP 连接配置、扩展全局设置。明确路径无效时返回错误，不换一个隐含目录。

## 采集与后续处理

普通媒体标记只留下源身份、时间和观察事实，后续由用户 Agent 在明确处理指令下获取和裁切。网页文字等易失内容即时保存。现场录制必须由用户单独启用，仅对本次片段生效；未录下来的过去内容不会在后来被描述为已保存。

媒体原始连续段保留跳转顺序，`normalizedSegments` 只合并同次采集内的重叠，不用最小起点和最大终点填平快进缺口。计划获取与默认输出另按参数快照对各规范化区间添加预留；较大的预留可能让相邻计划范围重叠并合并，因此应同时查看原始区间与预留计划。明确选择仅原区间输出时，使用未加预留的规范化区间。

用户点击结束时冻结真实连续段和结束点。现场录制可以继续取得尾部预留；这段时间仍保存播放观察事件和实际覆盖，但不再扩展真实区间，也不会再次叠加预留时长。内容脚本与后台都检查这条边界，避免迟到的进度消息改变结束范围。

一条采集记录独立领取和回写，一条记录可以有视频和音频等多个产物。跨记录拼接由外部 Agent 执行，不属于 Clipper 的采集管理逻辑。ASR、OCR、摘要与内容理解继续属于外部系统。

## 模块

| 路径 | 职责 |
|---|---|
| `packages/core` | 数据契约、参数校验、IndexedDB、范围规范化与业务事务 |
| `apps/extension` | 页面采集、侧栏/独立管理页、录制、浏览器事件、Native Host 接线 |
| `packages/mcp` | 标准 MCP、broker、Native Messaging、安装与诊断、文件交接 |
| `docs/agent-workflow.md` | Agent 处理规则、执行工具选择和结果验证说明 |
| `scripts` | 构建、LSP、打包、测试素材服务 |
| `tests` | 领域、通信和浏览器验收 |

技术选型与实际兼容性分别记录。原型通过之前，不将 Native Host 的文档能力视为真实连接通过，也不将某个浏览器通过推广为所有系统都已支持。
